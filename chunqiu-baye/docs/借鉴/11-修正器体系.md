## 一、什么是"修正器"

**一句话：修正器 = 一个可复用的、带名字的"效果包"。**

```
不给每个事件单独写"金收入 +25%"
而是定义一个修正器 "丰收" = { 金收入 +25% }
然后到处引用 "丰收"
```

**好处**：
- 复用（一个修正器多处使用）
- 可叠加/可移除（加 buff / 去 buff）
- 模组可扩展（加新修正器不用改代码）

## 二、🔴 CK3：修正器（官方说明）

> **来源等级：【官方文档】** —— `common/modifiers/_modifiers.info`（全文）

**官方原文**：

```txt
In this folder, character modifiers are defined

The modifers are on the format:

modifer_key = {
    icon = icon_name

    # Effects, such as
    # tax_mult = 0.25
    # county_opinion_add = -30
}

"modifier_key" is the name of the modifier, that is used in effects to apply it
"icon" decides which modifier icon to use.
if it ends in positive or negative, the name of the modifier will be colored appropriately
```

**解读**：

| 字段 | 作用 |
|---|---|
| `modifier_key` | 修正器的名字（用于脚本引用） |
| `icon` | 图标 |
| 其他键 | **效果**，如 `tax_mult = 0.25` |

> 💡 **`icon` 以 positive/negative 结尾会自动着色** —— 红/绿。

### 2.1 真实例子（【文件确证】）

```txt
county_base_modifier = {
    icon = county_modifier_control_positive
    monthly_county_control_change_add = 0.1
}

siege_modifier = {
    icon = county_modifier_development_negative
    development_growth_factor = -5
    monthly_county_control_change_factor = -5
}

occupation_modifier = {
    icon = county_modifier_development_negative
    development_growth_factor = -5
    monthly_county_control_change_factor = -5
}
```

> 💡 **注意 `siege_modifier` 和 `occupation_modifier` 内容一样** ——
> 但**名字不同**。这样脚本可以按语义引用（"被围城" vs "被占领"）。

### 2.2 修正器的三种作用域（【文件确证】）

CK3 的修正器按**作用对象**分文件：

| 文件 | 作用域 |
|---|---|
| `00_basic_modifiers.txt` | 人物基础（技能修正） |
| `00_county_modifiers.txt` | 郡（省） |
| `00_province_modifiers.txt` | 领地 |
| `00_health_modifiers.txt` | 健康 |
| `00_governance_lifestyle_modifiers.txt` | 治理生活方式 |
| `00_yearly_event_modifiers.txt` | 年度事件 |

**基础修正器举例**（【文件确证】）：

```txt
intrigue_modifier = {
    scheme_discovery_chance_mult = 0.01
    owned_hostile_scheme_success_chance_add = 1
}

martial_modifier = {
    attacker_advantage = 0.5
    defender_advantage = 0.5
}
```

> 💡 **技能本身也是修正器** —— `martial_modifier` 就是"军事技能"带来的效果。
> **这让"技能"和"事件 buff"用同一套机制**，实现统一。

### 2.3 修正器的命名约定（【文件确证】）

CK3 的修正器名字带后缀，表明类型：

| 后缀 | 含义 | 例子 |
|---|---|---|
| `_add` | 加法 | `county_opinion_add = 10` |
| `_mult` | 乘法 | `tax_mult = 0.25` |
| `_factor` | 因子 | `development_growth_factor = -5` |

> 💡 **命名自带语义** —— 看名字就知道是加法还是乘法。

## 三、HOI4：修正器定义

> **来源等级：【文件确证】** —— `common/modifier_definitions/`

HOI4 把修正器**定义**和**使用**分开：

```
common/modifier_definitions/   # 定义修正器长什么样
common/modifiers/              # 具体的修正器实例
common/dynamic_modifiers/      # 动态修正器
common/opinion_modifiers/      # 好感修正器
common/resistance_compliance_modifiers/  # 抵抗/顺从
```

**目录结构说明**：

| 目录 | 作用 |
|---|---|
| `modifier_definitions` | 修正器的**类型定义** |
| `modifiers` | 修正器**实例** |
| `dynamic_modifiers` | 运行时动态生成的 |
| `opinion_modifiers` | 专门管好感 |

> 💡 **"定义"和"实例"分离** —— 这是比 CK3 更进一步的设计，
> 让修正器有**类型系统**。

---

## 四、EU4：事件修正器

> **来源等级：【文件确证】** —— `common/event_modifiers/`

EU4 的修正器主要服务于**事件**：

```
event_modifier = {
    icon = ...
    <效果>
    <持续时间>
}
```

**另外还有**：
- `common/triggered_modifiers/` —— 条件触发的修正器
- `common/province_triggered_modifiers/` —— 省份条件修正器

> 💡 **`triggered_modifiers` 很实用** ——
> "满足条件就自动生效"，不用手工加/减。
