## 一、HOI4 最强的是什么

| 领域 | 强在哪 | 对应我们 |
|---|---|---|
| **🔴 AI 决策（明文开放）** | AI 的所有偏好都是**可读可改的数据表** | `scripts/ai/AIManager.lua` |
| **生产系统** | 工厂 / 效率 / 资源，工业化的完整模拟 | 未做 |
| **军事组织** | 师编制、战斗宽度、补给 | 征兵 / 调军 |
| **国家焦点树** | 树状决策，历史剧本感 | `TechSystem` |

> **🔴 和 CK3 的关键区别**：CK3 把 AI 藏进引擎（`common/ai/` 都没有），
> **HOI4 把 AI 完全开放**（`common/ai_strategy/` 等 60+ 个 token）。
> **想看 AI 决策逻辑，HOI4 才是该学的那一个。**

## 二、🔴 AI 决策系统（最高价值，全开放）

> **来源等级：【文件确证】**

### 2.1 策略条目的结构

`common/ai_strategy/*.txt` —— 每个策略是一个命名块：

```txt
GER_unit_production = {
    allowed = { original_tag = GER }      # 谁能用
    enable  = { always = yes }            # 何时激活
    abort   = { always = no }             # 何时取消
    ai_strategy = {
        type  = role_ratio
        id    = infantry
        value = 75
    }
}
```

### 2.2 🔴 核心打分公式

原文 `common/ai_strategy/documentation.info` 第 107 行：

> **"Unit ratios are calculated as a base of 100 plus the value indicated in the strategy."**
> （兵种比例 = 基础 100 + 策略里写的 value）

```
value = -40  →  只追求 60% 的目标（100 - 40 = 60）
value = +75  →  追求 175% 的目标
```

**`conquer` / `antagonize` / `befriend` 的 value 是可叠加的加权分。**

> 💡 **这是最有价值的一条设计**：AI 的"想法"不是代码，是**一张能改的表**。

### 2.3 策略 token 全表（约 60 个，五类）

| 类别 | token |
|---|---|
| **外交** | `alliance` `antagonize` `befriend` `conquer` `contain` `invade` `prepare_for_war` `consider_weak` `protect` `influence` `declare_war` `avoid_starting_wars` |
| **前线/陆军** | `area_priority` `front_control` `front_unit_request` `garrison` `invasion_unit_request` `put_unit_buffers` `spare_unit_factor` |
| **海军** | `naval_invasion_focus` `naval_convoy_raid_region` `strike_force_home_base` |
| **生产/资源** | `build_army` `build_ship` `build_building` `building_target` `equipment_production_factor` `role_ratio` `unit_ratio` `template_prio` `research_tech` `factory_build_score_factor` |
| **情报/空军** | `operative_mission` `operative_operation` `strategic_air_importance` |

### 2.4 兵力构成目标（默认值）

`common/ai_strategy/default.txt`（非主要国默认）：

```txt
role_ratio（陆军师类型占比）:
    infantry    = 80
    mountaineers= 4
    armor       = 2
    paratroopers= 0
    marines     = 0

unit_ratio（空军/海军装备占比）:
    fighter        = 80
    cas            = 5
    tactical_bomber= 5
    capital_ship   = 10
    screen_ship    = 40
    submarine      = 10
    convoy         = 15

equipment_production_factor（装备生产倾向）:
    infantry = 40
    artillery= 25
    fighter  = 35
```

`common/ai_strategy/GER.txt`（德国覆写）：`infantry=75`、`armor=-17`、`artillery=100`、`anti_air=25`。

> 💡 **注意 `armor = -17`**：负值表示"少造装甲，靠国策/学说补足"。
> **这是"用数据表达策略倾向"的好例子** —— 不用改代码就能表达"德国优先炮兵"。

### 2.5 宣战决策（关键常量）

`common/defines/00_defines.lua`：

```lua
DILPOMATIC_ACTION_DECLARE_WAR_WARGOAL_BASE = 50,  -- 每个战争目标的基础分（注意原文拼写 DILPOMATIC）
DIPLOMATIC_ACTION_RANDOM_FACTOR = 0.5,            -- 50% 的分数随机决定
DECLARE_WAR_RELATIVE_FORCE_FACTOR = 0.5,          -- 相对国力的权重
DECLARE_WAR_NOT_NEIGHBOR_FACTOR = 0.25,           -- 非邻国 ×0.25
IRRATIONALITY_LAMBDA = 200,                       -- 泊松随机：领袖"发疯"概率
```

> 💡 **`IRRATIONALITY_LAMBDA = 200`** 是很有意思的设计：
> 让 AI **大部分时候理性，偶尔"发疯"**（原文注释举例"斯大林征服美国"）。
> 这让 AI **可预测但不死板**。

### 2.6 国家焦点选择

`common/ai_focuses/*.txt` + `common/ai_strategy_plans/*.txt`：

- **历史模式**：策略计划里 `ai_national_focuses = { 顺序列表 }`，AI 按列表顺序点
  （`SOV_historical_strategy_plan.txt` 每项还标了目标日期如 `#1938`）
- **研究权重**：`ai_focus_military_equipment = { research = { infantry_weapons = 50.0  infantry_tech = 15.0 } }`
- **焦点打分**：`FOCUS_TREE_CONTINUE_FACTOR = 1.5`（更倾向沿当前树枝继续）

### 2.7 AI 师编制与装备

`common/ai_templates/*.txt` —— 为每个 role 定义模板，含**逐属性权重**：

```
stat_weights = { max_organisation = 30, max_strength = 0.8, defense = 1.1 }
target_width = ...
match_value  = ...
```

> 💡 **AI 选装备不是硬编码，而是对每个属性配权重求和。** 这个模式可以复用。

**XP 使用欲望**（`NAI` 段）：

```lua
DESIRE_USE_XP_TO_UPDATE_LAND_TEMPLATE = 2.0/天   -- 最高
UNLOCK_LAND_DOCTRINE = 0.5/天
```

AI 攒"欲望值"，满了就花在欲望最高的项上。

### 2.8 兵力分配与前线

`NAITheatre` 段：

- 战区按首都距离生成（`HOME_THEATRE_DEPTH_RESTRICTION = 2`）
- 每 `AI_UPDATE_ROLES_FREQUENCY_HOURS = 48` 小时更新 role 分配
- 前线激进度三档：`PLAN_ATTACK_MIN_ORG_FACTOR_{LOW=0.85, MED=0.7, HIGH=0.4}`
- `front_control` 可强制指定 `execution_type = rush / careful / balanced`

### 3.2 生产效率

`00_defines.lua`：

```lua
BASE_FACTORY_SPEED = 5,               -- 民用厂基础速度
BASE_FACTORY_SPEED_MIL = 4.50,        -- 军工厂
BASE_FACTORY_SPEED_NAV = 2.5,         -- 船坞
BASE_FACTORY_START_EFFICIENCY_FACTOR = 10,   -- 起始效率 10%
BASE_FACTORY_MAX_EFFICIENCY_FACTOR = 50,     -- 上限 50%
BASE_FACTORY_EFFICIENCY_GAIN = 1,            -- 日增
EFFICIENCY_LOSS_PER_UNUSED_DAY = 1,          -- 闲置日损
```

**换产线惩罚**（保留效率）：换变体 `90%`、同族 `70%`、父子 `30%`、同原型 `20%`。

**单线厂数上限**：民用 `15`、军用 `150`。

### 3.3 资源

6 种：`oil / aluminium / rubber / tungsten / steel / chromium`（`00_resources.txt`），每种 `cic = 0.125`。

- 资源不足每厂惩罚：`PRODUCTION_RESOURCE_LACK_PENALTY = -0.05`
- 基建每级资源加成：`INFRASTRUCTURE_RESOURCE_BONUS = 0.2`
- 燃料来源：`FUEL_RESOURCE = "oil"`

## 四、军事组织与战斗

> **来源等级：【文件确证】**

### 4.1 师编制

- 编制盘上限：`MAX_DIVISION_BRIGADE_WIDTH = 5 × 5`
- **单营属性**（`units/infantry.txt`）：

```
步兵营：combat_width = 2, max_strength = 25, max_organisation = 60,
        manpower = 1000, training_time = 90天, supply_consumption = 0.06,
        need = { infantry_equipment = 100 }
炮兵营：combat_width = 0, manpower = 300
```

> 💡 **注意炮兵 `combat_width = 0`** —— 炮兵不占宽度，所以"堆炮兵"是经典战术。
> **这是"用宽度设计逼出战术"的好例子。**

### 4.2 战斗宽度（按地形）

`terrain/00_terrain.txt`：

| 地形 | 战斗宽度 |
|---|---:|
| 城市 | 96 |
| 平原 | 90 |
| 森林 / 丛林 | 84 |
| 丘陵 | 80 |
| 沼泽 | 78 |
| 山地 | 75 |

- 超宽惩罚：`COMBAT_OVER_WIDTH_PENALTY = -1.5%/点`，封顶 `-0.33`
- 堆叠惩罚：超过 `COMBAT_STACKING_START = 8` 个师起，每师 `-0.02`

### 4.3 补给

`NSupply` 段：

```
首都补给 = 5.0 + 0.3×民用厂 + 0.6×军工厂 + 0.4×船坞
补给沿铁路/河流扩散，每省递减（CAPITAL_INITIAL_SUPPLY_FLOW = 5.0）
铁路每级 +5.0 flow
缺补给最大损耗：OUT_OF_SUPPLY_ATTRITION = 0.20
军队自带宽限：SUPPLY_GRACE = 72 小时
```

### 4.4 战斗结算

```lua
LAND_COMBAT_ORG_DICE_SIZE = 4,          -- 组织度骰子
LAND_COMBAT_STR_DICE_SIZE = 2,          -- 兵力骰子
LAND_COMBAT_STR_DAMAGE_MODIFIER = 0.060,  -- 全局兵力伤害系数
LAND_COMBAT_ORG_DAMAGE_MODIFIER = 0.053,  -- 全局组织度伤害系数
BASE_CHANCE_TO_AVOID_HIT = 90,            -- 有防御时的闪避
CHANCE_TO_AVOID_HIT_AT_NO_DEF = 60,       -- 无防御时
```

**地形进攻惩罚**：山地 `-0.5`、沼泽 `-0.4`、城市/丛林 `-0.3`、丘陵 `-0.25`、森林 `-0.15`；过河 `-0.3`（小河）/ `-0.6`（大河）；要塞 `-0.15`。

**战斗战术**（`combat_tactics.txt`）：

- 每 `TACTIC_SWAP_FREQUENCEY = 12` 小时抽一次
- 战术有 `base = { factor }` 权重 + `countered_by` 克制 + `phase`
- 将领 traits 影响抽取（如 `aggressive_assaulter` +2 权重）

## 五、国家焦点树

> **来源等级：【文件确证】**

`national_focus/germany.txt`：

```
focus = {
    id = GER_four_year_plan
    icon / x / y / relative_position_id
    prerequisite = { focus = GER_xxx }          # 前置
    mutually_exclusive = { focus = GER_yyy }    # 互斥
    available = { <trigger> }                   # 显示但灰
    bypass  = { <trigger> }                     # 条件满足直接跳过并给奖励
    cost = 10                                   # 1点 = 7天 → 10点 = 70天
    ai_will_do = { factor = 12 }                # AI 权重
    completion_reward = { add_tech_bonus / add_building_construction / ... }
}
```

- `FOCUS_PROGRESS_PEACE/WAR = 1`
- `MAX_SAVED_FOCUS_PROGRESS = 10`（未选焦点时最多存 10 天进度）
- **连续焦点**（1.11+）：`daily_cost = 1`（每日扣政治点），需先完成 `MIN_FOCUSES_FOR_CONTINUOUS = 10` 个国策

## 六、玩家操作流程

### 6.1 经济运营

```
1. 建民用工厂 → 攒产能
2. 建军用工厂 → 造装备
3. 铺基建 → 加资源产出 + 加速建造
4. 分配资源 → 钢/铝/橡胶/钨/铬，不够就惩罚
```

### 6.2 军事

```
1. 设计师编制（编制盘 5×5）
2. 生产装备 → 训练师
3. 部署到前线 → 选将领
4. 战斗：宽度限制参战师数，超宽惩罚
5. 补给：靠铁路扩散，断了就损耗
```

### 6.3 国策树

```
1. 攒政治点
2. 点国策（1点 = 7天）
3. 互斥国策要选边
4. 解锁奖励 → 推动战略方向
```

## 七、设计意图 —— 为什么玩家会开心

> **来源等级：【推测】** —— 以下是我对设计动机的推理，P 社未明说。

| 技巧 | 为什么这样设计 | 玩家感受 |
|---|---|---|
| **AI 权重全开放** | 让 mod 能改 AI，生态才活 | 「我能让 AI 更凶」 |
| **"基础 100 + value"** | 一个统一公式，好懂好调 | — |
| **负值表达倾向** | `armor = -17` 比"设成 0"信息量大 | — |
| **`IRRATIONALITY_LAMBDA`** | 让 AI 偶尔发疯，避免被摸透 | 「这AI真敢打」 |
| **炮兵宽度 0** | 制造"堆炮兵"的战术空间 | 「原来炮兵不占位」 |
| **战斗宽度按地形** | 山地只能展开少量部队 | 「山地难打」 |
| **补给靠铁路** | 让后勤成为真实约束 | 「补给断了，完了」 |
| **换产线惩罚** | 决策有代价，不能随便改 | 「换产线要想清楚」 |

## 八、我们能借鉴什么

### 8.1 🔴 最高价值：AI 数据表化

**这是我们最该学的。** 对比：

| | CK3 | HOI4 |
|---|---|---|
| AI 逻辑位置 | C++ 引擎，**改不了** | **明文数据表，随便改** |
| 我们能看到吗 | ❌ | ✅ |

**建议给 `AIManager.lua` 引入同样的模型**：

```lua
-- 类似 HOI4 的做法：AI 偏好做成数据表
AI_STRATEGY = {
    { type = "role_ratio",  id = "infantry", value = 80 },
    { type = "conquer",     id = "邻国A",    value = 50 },
    { type = "befriend",    id = "强国B",    value = 30 },
}
-- 打分 = 基础 100 + value
```

**好处**：
- 策划调 AI 不用改代码
- 模组能改 AI 行为（你的 `docs/后续制作方向.md` 提过要"模组底层能力"）
- 出问题好排查（能直接看到 AI 的"想法"）

### 8.2 其他可借鉴点

| 借鉴点 | 对应我们 | 优先级 |
|---|---|---|
| **AI 权重表** | `AIManager.lua` | 🔴 高 |
| **"基础 100 + value" 打分** | AI 目标选择 | 🔴 高 |
| **随机性参数**（`IRRATIONALITY_LAMBDA`） | AI 不可预测性 | 🟡 中 |
| **战斗宽度按地形** | `CombatRules` | 🟡 中 |
| **补给沿路径扩散** | `MilitaryLogistics` | 🟡 中 |
| **换产线惩罚** | 无对应 | ⚪ 低 |
| **国策树** | `TechSystem` | ⚪ 低 |

### 8.3 ⚠️ 不能照搬的

| 为什么 |
|---|
| HOI4 是**二战工业战**，我们是**春秋战国**。工厂/装备体系不适用 |
| 它的战斗宽度是配"师"设计的，我们的是"省驻军" |
| 数值必须配我们自己的体系（参见 CK3 文档 §5.5 的实验） |
