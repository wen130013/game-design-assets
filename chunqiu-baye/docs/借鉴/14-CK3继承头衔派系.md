## 一、🔴 头衔层级（Landed Titles）

> **来源等级：【官方文档】** —— `_landed_titles.info`

### 1.1 五级嵌套结构（官方原文）

```txt
e_my_empire = {          # e_ = 帝国
    k_my_kingdom = {     # k_ = 王国
        d_my_duchy = {   # d_ = 公国
            c_my_county = {   # c_ = 郡
                b_my_barony = {  # b_ = 男爵领
                }
            }
        }
    }
    c_my_other_county = {}
}
```

**前缀即层级**：

| 前缀 | 层级 |
|---|---|
| `e_` | 帝国 |
| `k_` | 王国 |
| `d_` | 公国 |
| `c_` | 郡 |
| `b_` | 男爵领 |

### 1.2 🔴 关键设计：层级是"嵌套"定义的

**官方原文**："Titles are defined from top to bottom in the hierarchy."

**这意味着**：**层级关系写在数据里**，不是靠外键关联。

> 💡 **对我们的意义**：
> 我们的省份是**扁平**的（2457 省，无层级）。
> CK3 的"省 → 郡 → 公国 → 王国 → 帝国"是**树状**的。
> **如果想做"郡县制/封建制"的差异，这个层级结构值得参考。**

### 1.3 头衔属性（官方原文）

```txt
k_my_title = {
    can_create = {}                 # 创建条件（root = 想创建的角色）
    can_create_on_partition = {}    # 分割继承时的创建条件
    can_be_named_after_dynasty = no # 是否随王朝命名
    cultural_names = {
        X = Y    # 文化 X 持有 → 用 Y 本地化键
    }
}
```

**真实例子**（【文件确证】）：

```txt
k_papal_state = {
    color = { 255 249 198 }
    color2 = { 220 220 0 }
    definite_form = yes
    ruler_uses_title_name = no
    landless = yes              # ⚠️ 无地头衔
    capital = c_roma
    ai_primary_priority = { add = @always_primary_score }  # 1000
    destroy_if_invalid_heir = yes
    no_automatic_claims = yes
}
```

> 💡 **`landless = yes`（无地头衔）** —— 教皇国可以没有领土。
> **`ai_primary_priority = 1000`** —— AI 把它当"首要头衔"的权重。

### 1.4 本地化变量（有意思）

```txt
@correct_culture_primary_score = 100
@better_than_the_alternatives_score = 50
@always_primary_score = 1000
```

**用 `@变量` 定义常量，后面引用** —— 避免魔数散布。

## 二、🔴 继承选举（Succession Election）

> **来源等级：【官方文档】** —— `_succession_election.info`

### 2.1 结构（官方原文）

```txt
feudal_elective = {
    candidates = {              # 谁能当候选人
        add = {
            type = holder_direct_vassals
            limit = {}          # 额外条件
        }
        limit = {}
    }

    electors = {                # 谁能投票
        max = 10                # 最多几个选举人（<0 = 不限）
        priority = {}           # 优先级 MTTH
    }

    elector_vote_strength = {}  # 每票的权重
    candidate_score = {}        # AI 怎么给候选人打分
}
```

### 2.2 🔴 候选人类型（官方列出的 7 种）

```
title_claimants             # 头衔宣称者
title_dejure_vassals        # 法理封臣
holder                      # 当前持有者
holder_direct_vassals       # 当前持有者的直属封臣
holder_spouses              # 配偶
holder_close_family         # 近亲
holder_close_or_extended_family  # 近亲或远亲
holder_dynasty              # 王朝成员
```

> 💡 **"候选人范围"是可以配的** ——
> 不同继承法（封建选举 / 长子继承 / 分割）就是**不同的候选人和选举人集合**。

### 2.3 关键机制

| 机制 | 说明 |
|---|---|
| `max = 10` | 选举人上限 |
| `elector_vote_strength` | 票权可不等（大国封臣票更重） |
| `candidate_score` | AI 投票打分 |
| **当前持有者不能当候选人** | 官方明确说明 |

## 三、🔴 派系（Factions）—— 叛乱机制

> **来源等级：【官方文档】** —— `_factions.info`（8.4 KB，最详细的一份）

### 3.1 两种派系（【文件确证】）

```
liberty_faction      # 自由派系（要更多权利）
claimant_faction     # 宣称派系（要换君主）
```

### 3.2 🔴 完整的字段（官方原文节选）

```txt
faction_name = {
    name / description / short_effect_desc    # 动态文案

    demand = {}              # 发难时执行的效果
    update_effect = {}       # 每 N 天执行
    on_declaration = {}      # 宣战时执行
    character_leaves = {}    # 成员离开时
    leader_leaves = {}       # 领袖离开时

    # 🔴 AI 相关
    ai_join_score = {}       # AI 加入的意愿（MTTH）
    ai_create_score = {}     # AI 创建的意愿
    ai_demand_chance = {}    # AI 发难的意愿
    discontent_progress = {} # 不满进度怎么涨
    power_threshold = value  # 力量阈值（超过才开始涨不满）

    # 🔴 各种合法性检查
    is_valid = {}
    is_character_valid = {}
    is_county_valid = {}
    can_character_join = {}
    can_character_create = {}
    can_character_become_leader = {}
    can_county_join = {}
    can_county_create = {}

    # 开关
    character_allow_create = yes
    character_allow_join = yes
    player_can_join = no          # ⚠️ 玩家能否加入
    multiple_targeting = no
    casus_belli = key             # 发难时用的 CB
    inherit_membership = no       # 继承是否继承派系成员身份
    requires_county = no
    requires_character = yes
    sort_order = 1..n
}
```

### 3.3 🔴 三个核心设计

**① 派系有"力量阈值"**

```txt
power_threshold = value    # 超过才涨不满
discontent_progress = {}   # 不满怎么涨
```

**逻辑**：派系力量 **超过阈值** → 不满开始涨 → 涨满 → 发难。

> 💡 **这让叛乱是"渐进"的，不是突发的** —— 玩家有时间反应。

**② AI 参与是"打分制"**

```txt
ai_join_score = {}      # 加入意愿
ai_create_score = {}    # 创建意愿
```

**官方说明**（原文）：

> "Note that the score is then modified by code to weigh in the effects of
> **Boldness/Dread, Energy and Rationality**."

**翻译**：AI 算完基础分后，**引擎还会按"胆量/恐惧、精力、理性"修正**。

> 💡 **这是"数据 + 引擎"结合的例子** ——
> 脚本给基础意愿，引擎按性格修正。

**③ 派系可以"拉郡"（county）**

```txt
can_county_join = {}
county_power = {}    # 郡的绝对力量
```

**官方说明**：

> "The final power is calculated as **ratio of this power and the target's military strength**."

**翻译**：郡的力量 = 该郡力量 ÷ 目标军力。

> 💡 **即"你的军队越强，叛乱相对越弱"** —— 自然的压制机制。

### 3.4 其他细节

```txt
county_can_switch_to_other_faction = no   # 郡能否跳到更好的派系
sort_order = 1..n                          # UI 排序
inherit_membership = no                    # 继承是否延续派系身份
```

## 五、我们能借鉴什么

### 5.1 值得学的（按优先级）

| 借鉴点 | 来源 | 为什么好 |
|---|---|---|
| **🔴 派系/叛乱机制** | CK3 | 让"内部不稳"成为玩法，你 `docs/后续制作方向.md` 提过"复国基础" |
| **🔴 头衔层级** | CK3 | 想做"郡县制 vs 封建制"差异的话，这个结构有用 |
| **力量阈值 + 不满渐进** | CK3 | 叛乱有预警，不突然 |
| **候选人范围可配** | CK3 | 不同继承法 = 不同候选人集合 |
| **AI 打分 + 性格修正** | CK3 | 数据 + 引擎结合 |

### 5.2 🔴 最契合我们的：派系/叛乱

**你 `docs/后续制作方向.md` 提到**：

> "**局势持续变化**：有扩张、**文化不满、复国基础**"
> "更连贯的事件、外交变化、发展阻力，让中后期仍有新局面"

**CK3 的派系机制正好解决这个**：

| CK3 | 我们可以 |
|---|---|
| `liberty_faction`（要权利） | 旧贵族要特权？ |
| `claimant_faction`（要换君主） | 公族夺位？ |
| `power_threshold` | 力量超过才发难 |
| `discontent_progress` | 不满逐月累积 |

**这能让"中后期无事可做"变成"要防内乱"。**

### 5.3 ⚠️ 不能照搬的

| 为什么 |
|---|
| CK3 是**欧洲封建制**（公国/伯爵/男爵），我们是**郡县制** |
| 它的"法理头衔"体系（dejure）我们没有 |
| 数值和层级都要重新设计 |
