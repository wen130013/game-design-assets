## 一、🔴 EU4 外交接受度：完整的加法评分

> **来源等级：【文件确证】** —— `common/new_diplomatic_actions/france_diplomatic_actions.txt`

### 1.1 结构：`add_entry` 逐项累加

```txt
ai_acceptance = {
    add_entry = {
        name = <这条叫什么>
        limit = { <什么条件下生效> }
        export_to_variable = { which = ai_value  value = <加多少> }
    }
    ...
}
```

**最后 `ai_value` 就是 AI 的接受分** —— 高于阈值就答应。

### 1.2 🔴 真实的打分项（法国附庸他国）

| 条目 | 条件 | 分数 |
|---|---|---:|
| `ME_FROM_ATTITUDE_TOWARDS_ROOT` | 对方是**盟友/友好** | **+10** |
| 同上 | 对方**受威胁** | **+20** |
| 同上 | 对方**中立** | **-10**（先 +10 再 ×-1） |
| 同上 | 对方**敌视/宿敌/愤怒** | **-1000**（直接否决） |
| `MODIFIER_DIPLO_SKILL` | 外交声誉 | `modifier:diplomatic_reputation` |
| `ME_ROOT_FROM_MILITARY_POWER_COMPARED` | 军力对比 | 分档（见下） |
| `ME_FROM_HAS_SUBJECTS` | 对方有属国 | 修正 |
| `ME_FROM_DEVELOPMENT` | 对方发展度 | `total_development ÷ (−3)` |
| `ME_ROOT_OWNS_FROM_CORE_PROVINCES` | 我占他核心 | 修正 |
| `BORDER_DISTANCE` | 边境距离 | 修正 |

### 1.3 🔴 三个设计要点

**① 态度是"一票否决"级别的权重**

```
友好 +10  →  中立 -10  →  敌视 -1000
```

**-1000 是"直接否决"** —— 不是线性递减，而是**断崖式**。
**设计意图【推测】**：态度差到一定程度，别的条件再好也没用。

**② 军力对比是分档的**

```txt
ME_ROOT_FROM_MILITARY_POWER_COMPARED
    → 用 divide / multiply / change_variable 逐项算
    → 极弱 -40、均衡 0、强 +X
```

**③ 对方越大越不愿屈服**

```
ME_FROM_DEVELOPMENT = total_development ÷ (−3)
```

**发展度越高，分数越负** —— 大国不愿当附庸。

> 💡 **这套机制的价值**：**完全用脚本变量加法实现**，
> 可读、可调、可 mod。**这是 CK3 学不到的。**

## 二、EU4 宣战理由（CB）的完整结构

> **来源等级：【文件确证】** —— `common/cb_types/`

### 2.1 CB 结构

```txt
cb_xxx = {
    valid_for_subject = no        # 附庸能否用
    is_triggered_only = yes       # 只由脚本触发
    months = 120                  # CB 有效期（月）
    prerequisites = { ... }        # 获得条件
    war_goal = <wargoal_id>        # 关联的战争目标
    holy_war = yes                # 圣战标记
    attacker_disabled_po = { ... } # 禁用某些和约条款
}
```

### 2.2 🔴 战争目标（wargoal）结构

> **来源等级：【文件确证】** —— `common/wargoal_types/`

```txt
HAB_convert_to_religion = {
    type = take_capital            # 类型：占领首都

    attacker = {
        badboy_factor = 0.5        # 侵略扩张系数
        prestige_factor = 1        # 威望系数
        peace_cost_factor = 0.4    # 和约成本系数 ← 关键
        peace_options = { po_change_religion }
    }

    defender = {
        badboy_factor = 1
        prestige_factor = 1
        peace_cost_factor = 1
        peace_options = { po_change_religion }
    }

    war_name = HAB_WAR_NAME
}
```

### 2.3 🔴 关键设计：攻守双方的系数不同

| 系数 | 攻方 | 守方 | 含义 |
|---|---:|---:|---|
| `badboy_factor` | **0.5** | 1 | **攻方侵略扩张减半** |
| `peace_cost_factor` | **0.4** | 1 | **攻方和约成本打折** |

> 💡 **有 CB 时，攻方的"政治代价"更低** ——
> 这就是 CB 的价值：**给你一个"正当理由"，让侵略更便宜**。
>
> **设计意图【推测】**：约束扩张节奏 —— 想扩张，先攒 CB。

### 3.3 🔴 AI 割地偏好（明文）

```json
{
    "AI_PEACE_DEMAND_PROVINCE_NEIGHBORING_WINNER_SCORE": 250.0,
    "AI_PEACE_DEMAND_PROVINCE_NEIGHBORING_WINNER_PERC": 500.0,
    "AI_PEACE_DEMAND_PROVINCE_NEIGHBORING_LOSER_SCORE": -125,
    "AI_PEACE_DEMAND_PROVINCE_NEIGHBORING_SEA": 40.0,
    "AI_PEACE_DEMAND_PROVINCE_DISTANCE": 30.0,
    "AI_PEACE_EXTRA_DEMAND_SURROUNDED_PROVINCES": true,
    "AI_ABANDON_DEMAND_PROVINCES_IF_ARE_NOT_CONNECTED": true
}
```

**解读**：

| 条件 | 分数 |
|---|---:|
| 邻接**胜方**的省 | **+250** |
| 邻接胜方的**百分比**加成 | **+500** |
| 邻接**败方** | **-125** |
| 临海 | +40 |
| 每单位距离 | -30 |
| **被包围的省** | 优先要 |

> 💡 **AI 割地是"有偏好"的** —— 优先要连成片的、被包围的。
> **不是随机割地。**
