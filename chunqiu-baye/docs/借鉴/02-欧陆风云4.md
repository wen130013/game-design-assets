## 二、外交系统

### 2.1 宣战理由（Casus Belli）

> **来源等级：【文件确证】** —— `common/cb_types/*.txt`（27 个文件）

**字段结构**（vanilla 格式）：

```txt
cb_xxx = {
    valid_for_subject = no        # 附庸能否用
    is_triggered_only = yes       # 只由脚本触发（非通用）
    months = 120                  # CB 有效期，月
    prerequisites = { ... }        # 获得条件
    war_goal = <wargoal_id>        # 关联的战争目标
    holy_war = yes                # 圣战标记
    attacker_disabled_po = { ... } # 禁用某些和约条款
}
```

**真实例子**（`france_missions_cb_types.txt`，mod 值）：

```txt
cb_grand_iberian_campaign = {
    valid_for_subject = no
    is_triggered_only = yes
    months = 60
    war_goal = annex_iberia
}

cb_fra_crusade_against_tur = {
    valid_for_subject = no
    is_triggered_only = yes
    months = 360
    holy_war = yes
    war_goal = superiority_crusade
}
```

**统计**（mod 值）：`valid_for_subject = no` 出现 47 次；`months` 分布 `120(15次) > 60(6次) > 240 > 360 > -1`。

> ⚠️ **重要区分**：这个 mod 的 CB **全是任务触发型**，**看不到 vanilla 的通用 CB**。
> vanilla 通用 CB（**来源等级：【社区反推】**）：`cb_conquest`（普通征服）、`cb_reconquest`（收复核心，AE 更低）、
> `cb_subjugation`（附庸）、`cb_holy_war`、`cb_crusade`、`cb_restore_personal_union`、`cb_claims` 等。

**设计意图【推测】**：CB 是"**开战的合法性令牌**"。

```
没有 CB 开战  →  付稳定度 + 大量 AE
有 CB 开战    →  AE 打折、和约成本打折
```

**这是 EU4 把"扩张欲望"约束在"外交规则"里的核心设计** —— 玩家不能随便打，必须攒 CB。

### 2.2 停战协议（Truce）

**文件确证**：

- `truce_with = FROM` 触发器（判断是否停战中）
- 外交动作 `is_allowed` 里普遍写 `NOT = { truce_with = FROM }` → **停战期内不能宣战**
- `add_truce_with = FROM` 效果（建立停战）

**⚠️ 停战时长公式在 defines 里，拿不到。**

社区反推（**【社区反推】，未确证**）：停战年限 = `5 + 战争分数/10`，上限 15 年。白和 5 年，割满 100 分约 15 年。

### 2.3 关系值（Opinion）

> **来源等级：【文件确证】** —— `common/opinion_modifiers/*.txt`

```txt
modifier_name = {
    opinion = 20        # 一次性加减的数值
    yearly_decay = 1    # 每年衰减多少
    min = -100          # 可选下限
    max = 15            # 可选上限
}
```

**真实例子**（mod 值）：

```txt
me_hab_spent_glory = { opinion = 150, yearly_decay = 0.5 }          # +150，慢衰减
me_hab_rejected_imperial_authority = { opinion = -50, yearly_decay = 1 }
po_make_french_hre_subject_opinion = { opinion = -100, yearly_decay = 2, min = -100 }
```

**统计**：`yearly_decay` 取值 `0.25 / 0.5 / 1 / 1.5 / 2 / 3 / 4 / 5`，**1 最常见（42 次）**。

> 💡 **opinion 是"慢变量"** —— 让外交有记忆，不能一夜翻盘。

### 2.4 附庸/属国类型

> **来源等级：【文件确证】** —— `common/subject_types/*.txt`

**明文可读的字段**：

```
joins_overlords_wars, can_fight_independence_war, takes_diplo_slot,
forcelimit_to_overlord, base_liberty_desire, liberty_desire_development_ratio,
can_be_integrated, trust_on_start
```

**例子**（`timar` 奥斯曼军事采邑，mod 值）：

```
base_liberty_desire = -10.0
liberty_desire_development_ratio = 0.25
trust_on_start = 50
joins_overlords_wars = yes
can_fight_independence_war = no
```

## 三、战争分数与和约

### 3.1 战争分数积累

> **⚠️ 引擎层，拿不到精确值**

文件里**没有**战争分数的计算公式。社区反推（**【社区反推】，未确证，且随版本变**）：

| 来源 | 社区说法 |
|---|---|
| 战斗 | 打赢一场大战斗最多 ±40%（**不同来源说法不一，我不确认**） |
| 占领省份 | 按 development 计，普通省约 0.5~1.5 分/省 |
| 封锁港口 | 贡献较小 |
| 单方面和约 | **只算占领+封锁，不算战斗分** |

> ⚠️ **诚实说明**：wiki 抓取的表格**精度不足**（不同版本冲突），建议标注为待核。

### 3.2 和约条款分数成本 —— EU4 最清晰的一块

> **来源等级：【文件确证】** —— `common/peace_treaties/*.txt`，**字段带官方注释**

```txt
po_xxx = {
    category = 6                 # 0-6，6 = "treaties" 标签页
    power_projection = vassalized_rival
    power_cost_base = 0.6        # 无 CB 时的外交点成本基数，随战争分数缩放
    prestige_base = 0.155        # 威望增减基数，随战争分数缩放
    ae_base = 0.3                # AE（侵略扩张）基数，随战争分数缩放
    warscore_cost = {
        all_provinces = 0.0      # 给方的全部省份
        no_provinces = 80.0      # 常数项
        owner_keeps = 0.0
        conquered = 0.0          # 被"索取省份"选中的省
        returned_core = 0.0      # 被"归还核心"选中的省
        released_nation = 0.0
        cancelled_subject = 0.0
        concede_colonial_region = 0.0
    }
    warscore_cap = -1            # 战争分数成本上限（非负才生效）
    requires_demand_independence = yes
    is_make_subject = yes        # 与其他"使对方成附庸"条款互斥
    requires_is_allowed = no
    is_visible = { ... }
    is_allowed = { ... }
    effect = { ... }
    ai_weight = { ... }
}
```

**数值统计**（mod 值）：

| 字段 | 值分布 |
|---|---|
| `ae_base` | 默认 **0**；出现 0.01 / 0.168 / 0.3 |
| `power_cost_base` | 默认 0；出现 0.6 / 1.0 |
| `prestige_base` | 默认 **0.01**（最常见）；出现 0.05 / 0.1 / 0.155 / 0.286 / 0.5 |
| `warscore_cost.no_provinces` | 10 / 20 / 30 / 40 / 60 / 80 |
| `warscore_cap` | 默认 -1；出现 30 / 60 / 80 / 100 |

> 💡 **机制意图**：**每条和约条款的成本 = 基数 × 战争分数**。
> 所以"战争分数"是外交里的**硬通货**，攒到 100 分才能割一大片地。
> **这是 EU4 最像"谈判桌"的设计。**

### 3.3 什么条件能强制和约

**文件确证**：

- 存在 `requestpeace`（求和）外交动作，其条件可被脚本覆写
- 和约能否达成由 AI 的 `ai_weight` + 战争分数决定（见 §五）
- **强制和约门槛在引擎**

- `add_core = TAG` / `remove_core = TAG` 是脚本效果

- **即 core 建造速度/成本可被修正项增减**

## 五、🔴 AI 决策（EU4 最强的一块）

> **来源等级：【文件确证】**

**核心结论：EU4 的 AI 权重确实明文可读，分四类结构。**

### 5.1 `ai_chance` —— 事件选项打分

**来源**：`events/*.txt`（**2184 处**）

```txt
option = { ai_chance = { factor = 80 } }   # 相对权重
option = { ai_chance = { factor = 20 } }   # → 80:20 概率
```

可带条件让权重归零：

```txt
modifier = { factor = 0, <trigger> }
```

### 5.2 `ai_will_do` —— "要不要做"

**来源**：`decisions/*`（**256 处**）、`common/buildings/*`、`common/new_diplomatic_actions/*`

**真实例子**（`decisions/ME_Rhineland_Decisions.txt`，mod 值）：

```txt
ai_will_do = {
    factor = 1                    # 基础意愿
    modifier = {
        factor = 0                # 钱不够 → 不做
        NOT = { treasury = 1500 }
    }
}
```

> 💡 **这是"AI 钱不够就不做"的明文表达。**

### 5.3 `ai_weight` / `ai_priority` —— 优先级

**来源**：`common/peace_treaties/*`、`missions/*.txt`、`common/holy_orders/*`

**和约条款**（必须用 `export_to_variable` 往 `ai_value` 写数）：

```txt
ai_weight = {
    export_to_variable = { variable_name = ai_value, value = 100 }
    limit = { always = yes }
}
```

`ai_value` 就是 AI 对该条款的评分。例：`po_austria_balkanize_france` value = **10000**（mod 想强制 AI 优先做）。

**任务**：

```txt
ai_weight   = { factor = 3, modifier = { factor = 0, <某区域已被盟友占> } }
ai_priority = { factor = 2 }
```

**圣战/文化转化**：`ai_priority = { factor = 0 }` + 注释 `#Let us not ruin cultures now`
→ **mod 作者直接用权重 0 禁止 AI 做某事。**

### 5.4 🔴 `ai_acceptance` —— 外交"答不答应"（最有价值）

**来源**：`common/new_diplomatic_actions/france_diplomatic_actions.txt`

这是**完整的 AI 接受度打分函数**，用 `add_entry` 逐项累加到 `ai_value`：

| 条目 | 条件 | 权重贡献 |
|---|---|---|
| `ME_FROM_ATTITUDE_TOWARDS_ROOT` | 对方态度 hostile/rivalry/outraged | **−1000**（直接否决） |
| `MODIFIER_DIPLO_SKILL` | 外交声誉 = 0 / ≠ 0 | `×2` / `×5` |
| `ME_ROOT_FROM_MILITARY_POWER_COMPARED` | 军力/军科对比 | 分档：极弱 −40、均衡 0、强 +X |
| `ME_FROM_DEVELOPMENT` | 对方总发展度 | `total_development ÷ (−3)` |
| `ME_ROOT_FROM_ARE_ALLIED` | 双方同盟 | +10 |
| `ME_FROM_HAS_MARRIAGE_WITH_ROOT` | 有联姻 | +10 |
| `ME_ROOT_FROM_NOT_SAME_RELIGION` | 不同宗教 | +10 |
| `ME_FROM_AI_PERSONALITY` | 对方 AI 性格 | 修正 |

> 💡 **这是 CK3 学不到的东西**：EU4 把"AI 愿不愿意接受外交提议"**完全用脚本变量加法实现**，
> **可读、可调、可 mod**。

### 5.5 AI 性格

**来源**：`common/ruler_personalities/me_ruler_personalities.txt`

```txt
me_enlightened_despote_personality = {
    ruler_allow = { chance = { modifier = { factor = 1, ADM = 6 } } }
    easy_war_chance_multiplier = 0.75    # 好战系数
    administrative_efficiency = 0.025
    global_unrest = -1
}
```

> 💡 **君主性格直接改 AI 行为参数**（如 `easy_war_chance_multiplier` 决定多好战）。

### 5.6 AI 态度枚举

```
attitude_hostile / attitude_rivalry / attitude_outraged / attitude_threatened
attitude_neutral / attitude_friendly / attitude_allied
```

**这七档态度是外交 AI 的顶层状态。**

**设计意图【推测】**：EU4 的 AI 之所以"看起来会做人事"，
是因为**它的决策参数全部暴露在脚本里** —— mod 作者能精确调"AI 多好战、多爱同盟、多少钱才建楼"。

## 六、玩家操作流程

### 6.1 外交

```
1. 攒 CB（宣战理由）—— 通过任务/事件/间谍
2. 看关系值（opinion）—— 决定 AI 会不会答应
3. 宣战 → 打仗 → 攒战争分数
4. 谈判：选和约条款，每条 = 基数 × 战争分数
5. 签停战协议（5~15 年不能再打）
```

### 6.2 扩张

```
1. 割地 → 造 core（花行政点）
2. 核心化 → 降低叛乱、提升收益
3. overextension 超 100% → 触发叛乱
```

## 七、设计意图 —— 为什么玩家会开心

> **来源等级：【推测】**

| 技巧 | 为什么这样设计 | 玩家感受 |
|---|---|---|
| **CB 令牌制** | 扩张要有"正当理由"，约束节奏 | 「我得先攒个 CB」 |
| **停战协议** | 强制冷静期，防止滚雪球 | 「打完了能喘口气」 |
| **关系值慢变量** | 外交有记忆 | 「关系是慢慢攒的」 |
| **和约 = 基数 × 分数** | 战争分数是硬通货 | 「再打一点就能割那块地」 |
| **AI 权重全明文** | mod 能改 AI，生态才活 | 「这 AI 挺像人」 |
| **七档态度** | 外交状态清晰可读 | 「他对我敌视」 |

## 八、我们能借鉴什么

### 8.1 🔴 最高价值：AI 三件套

**EU4 的 AI 决策完全脚本化**，三件套：

| 机制 | 用途 | 我们的对应 |
|---|---|---|
| `ai_chance` | 事件选项概率 | `EventSystem` |
| `ai_will_do` | 做不做某事 | `AIManager` |
| `ai_acceptance` | 外交答不答应 | `DiplomacySystem` |

**建议给我们的系统引入同样的模型**：

```lua
-- AI 接受外交提议的评分（照 EU4 的加法模型）
local score = 0
score = score + attitudeScore(对方对我的态度)        -- 敌视 → -1000
score = score + diploSkillScore(外交声誉)
score = score + militaryPowerScore(军力对比)
score = score + developmentPenalty(对方体量)         -- 越大越不愿附庸
score = score + (同盟 and 10 or 0)
score = score + (联姻 and 10 or 0)
-- score >= 阈值 → 答应
```

**好处**：
- AI 行为**可读可调**
- 模组能改（你的 `docs/后续制作方向.md` 提过要"模组底层能力"）
- 出问题好排查

### 8.2 其他可借鉴点

| 借鉴点 | 对应我们 | 优先级 |
|---|---|---|
| **CB 令牌制** | `DiplomacySystem` | 🟡 中 |
| **和约 = 基数 × 战争分数** | `PeaceSettlement` | 🟡 中 |
| **关系值慢变量**（yearly_decay） | `DiplomacySystem` | 🟡 中 |
| **AI 三件套** | `AIManager` / `DiplomacySystem` | 🔴 高 |
| **七档态度** | `DiplomacySystem` | ⚪ 低 |

### 8.3 ⚠️ 不能照搬的

| 为什么 |
|---|
| EU4 是**大航海/殖民时代**，CB 类型绑死它的宗教/王位体系 |
| 数值是 mod 值，**不是 vanilla** |
| 停战/战争分数公式**拿不到**，只能自己设计 |
