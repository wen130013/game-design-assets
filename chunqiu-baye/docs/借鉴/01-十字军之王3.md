## 🔴 来源等级标注（阅读前必看）

本文每个结论都标注来源等级。**不要把低等级当高等级用。**

| 标注 | 含义 | 可信度 |
|---|---|---|
| 【文件确证】 | 直接从原版配置文件读到，附文件路径 | ✅ **可依赖** |
| 【社区反推】 | 来自 wiki/社区实测，**未在文件中确证** | 🟡 方向可信，细节存疑 |
| 【推测】 | 推理，无直接证据 | ⚠️ 仅供参考 |

### 为什么需要这个标注

CK3 的架构是**两层**：

```
脚本层（明文文本）  ← 只放"可调参数"和"内容数据"  → 【文件确证】能拿到
      ↑ 读
引擎层（C++ 二进制） ← 真正的算法在这里，闭源      → 拿不到
```

**关键证据**：
- `common/on_action/combat_on_actions.txt` 全文仅 **31 行**，`effect = { }` 是**空的**
- 全仓库**没有** `common/ai/` 目录（对比：EU4/HOI4 都有）
- 说明战斗算法、AI 决策**都在引擎里**，脚本层碰不到

**因此**：
- 「伤害 = 攻击 × 0.03」这类**公式**——我们**拿不到**，只能靠社区反推
- 而**常量、兵种数值、相克关系**——我们**拿到了**，100% 精确

⚠️ **实践中发现社区来源互相矛盾**：同一个"优势加成"，两处 wiki 分别说 +1%/点、+5%/点，而原版文件里是 `ADVANTAGE_DAMAGE_SCALING_FACTOR = 2`。**三个数都不一样。** 这正说明"反推"不可靠。

## 二、战斗机制（核心）

### 2.1 🔴 重要更正：CK3 野战**没有士气**

**先说一个容易搞错的事实**：CK3 的野战**不使用士气（morale）**。

我把原版 `00_defines.txt` 里所有 `morale` 条目捞出来，结果是：

```
BASE_DEFENDER_MORALE = 50              ← 攻城
DEFENDER_MORALE_PER_FORT_LEVEL = 75    ← 攻城
BASE_DAILY_MORALE_LOSS = 1             ← 攻城
MIN_DAILY_MORALE_LOSS = 0.5            ← 攻城
STARVATION_MORALE_LEVELS = { ... }     ← 攻城（饥饿）
DISEASE_MORALE_LOSS_LEVELS = { ... }   ← 攻城（疫病）
DESERTION_MORALE_LOSS = 5              ← 攻城（逃亡）
```

**全部是攻城（siege）的。野战一个都没有。**

兵种定义里也没有 `morale` 字段：

```
light_footmen = {
    type = skirmishers
    damage = 10
    toughness = 16
    pursuit = 10
    screen = 16
    stack = 100
    counters = { heavy_infantry = 1 }
}
```

> ⚠️ **我们项目文档 `TODO.md:115` 记的「CK3 战斗：士气主导（士气崩 = 败退主因）」是错的。**
> 战斗结束的真正条件是 **坚韧（toughness）耗尽**。
> 「士气」是玩家社区的通俗说法，不是游戏机制。

### 2.2 战斗怎么结束

**坚韧耗尽**，不是士气崩溃。

```
每个士兵有 toughness 值
→ 承受的伤害消耗坚韧
→ 一方的总坚韧归零 = 该方战败
```

### 2.3 四个阶段

| 阶段 | 时长 | 能否撤退 | 说明 |
|---|---|---|---|
| **机动（Maneuver）** | `MANEUVER_PHASE_DAYS = 3` | — | 布阵，不产生伤亡 |
| **早期（Early）** | 约 7-12 天 | ❌ **不能** | 每日互伤；此阶段被击败 → 全军溃散 |
| **后期（Late）** | 接续 | ✅ 可以 | `MIN_DAYS_BEFORE_MANUAL_RETREAT = 14` 天后可手动撤 |
| **追击（Pursuit）** | `PURSUIT_PHASE_DAYS = 3` | — | 胜方追杀溃兵 |

**一场仗通常 8~12 天**。

> ⚠️ `TODO.md:115` 记的「一场仗 3~7 天」也是错的。

### 2.4 真实战斗常量（原版 `00_defines.txt`）

> **来源等级：【文件确证】** —— 以下全部直接从 `common/defines/00_defines.txt` 的 `NCombat` 段读出。
> ⚠️ **但注意**：这些是**常量**，不是**公式**。它们**怎么被使用**（乘什么、按什么顺序）在引擎里，**拿不到**。

```txt

COMBAT_EVENT_DAYS = 5                   # 骑士事件间隔

PURSUIT_PHASE_DAYS = 3                  # 追击阶段
MIN_DAYS_BEFORE_MANUAL_RETREAT = 14     # 多少天后可手动撤退

LEVY_ATTACK = 10                        # 征召兵攻击
LEVY_TOUGHNESS = 10                     # 征召兵坚韧
DAMAGE_SCALING_FACTOR = 0.03            # 伤害缩放（核心系数）
ADVANTAGE_DAMAGE_SCALING_FACTOR = 2     # 优势对伤害的影响

# ---- 战斗宽度 ----
BASE_WIDTH_RATIO = 1                    # 战斗宽度 = 守方规模 × 此值
MINIMUM_COMBAT_WIDTH = 100              # 宽度下限

# ---- 相克 ----
MEN_AT_ARMS_MAX_COUNTER = 0.9           # 被克制时伤害最多降低 90%
RATIO_FOR_MAX_COUNTER = 2.0             # 达到此比例触发最大克制
MEN_AT_ARMS_COUNTER_MODIFICATION = 6    # 被克制方所有掷骰的修正

# ---- 伤亡转化 ----
BASE_RATIO_CASUALTIES_CONVERSION = 0.3          # 主阶段：软伤亡→硬伤亡
BASE_RATIO_CASUALTIES_CONVERSION_PURSUIT = 1    # 追击阶段
PURSUIT_STAT_TO_PURSUIT_DAMAGE = 0.5            # 追击属性 → 实际伤害
BASE_TOUGHNESS_TO_PURSUIT = 0.05                # 无追击/掩护时，5% 软伤亡转硬伤亡
MINIMUM_PURSUIT_DAMAGE = 0.01                   # 高掩护也压不到 1% 以下

# ---- 骑士 ----
KNIGHT_DAMAGE_PER_PROWESS = 100         # 每点武勇给骑士的伤害
KNIGHT_TOUGHNESS_PER_PROWESS = 10       # 每点武勇给骑士的坚韧

# ---- 战争分数 ----
WAR_ATTACKER_COMBAT_SCORE_SCALE = 80    # 战斗给攻方的战争分缩放
WAR_ATTACKER_COMBAT_MAX_SCORE = 80      # 单场战斗攻方最多拿多少
MAX_ATTACKER_BATTLES_WAR_SCORE = 100    # 战斗总共能给攻方多少战争分
```

### 2.6 相克环

兵种通过 `counters = { 目标类型 = 系数 }` 定义克制：

```
light_footmen (散兵)  counters → heavy_infantry  (重步兵)
bowmen       (弓兵)  counters → skirmishers     (散兵)
```

**克制效果**：达到 `RATIO_FOR_MAX_COUNTER = 2.0` 比例时，被克制方伤害降低 `MEN_AT_ARMS_MAX_COUNTER = 0.9`（即 **-90%**）。

### 2.7 🔴 AI：架构可见，决策不可见

> **来源等级：【文件确证】**（架构部分）+ **【推测】**（设计意图部分）

**关键发现：CK3 的 `common/` 下有 49 个子目录，但唯独没有 `ai/`。**

对比 P 社其他游戏 —— CK2 / EU4 / HOI4 都有 `common/ai/`（里面是 AI 权重脚本）。**CK3 把它删了。**

CK3 的 AI 脚本层**只剩一个文件**：`common/defines/ai/00_ai.txt`（28 KB / 405 行）。

**这 405 行里全是"节奏参数"，不是决策逻辑**【文件确证】：

```txt
SHORT_TASK_TICK    = { 7   30  14  7   7   7 }   # 短任务重算间隔（按等级）
MEDIUM_TASK_TICK   = { 30  180 60  30  30  30 }  # 中任务
LONG_TASK_TICK     = { 60  360 180 60  60  60 }  # 长任务
RARE_TASK_TICK     = { 180 720 360 180 ... }     # 稀有任务
STRATEGY_TASK_TICK = { 180 720 360 ... }         # 战略任务

MINIMUM_TASKS_IN_TICK = 128     # 每 tick 至少算多少任务
MAX_TASKS_IN_TICK     = 192     # 上限
MAX_TICK_STALENESS    = 8       # 为了负载均衡，最多延后多久

BUDGET_CATEGORY = { 0.0  0.0  0.20  0.80 }  # 预算：战备/长期/短期
MIN_WAR_CHEST   = ...                        # 战备金下限
GOALS_PER_TYPE  = ...                        # 每类目标数量
IS_DESPERATE_REALM_SIZE_THRESHOLDS = ...     # 什么算"绝望"
```

**这 405 行没说什么**【文件确证】：

| 没明说的 | 为什么关键 |
|---|---|
| ❌ 怎么算"该不该宣战" | 只有"战备金"，没有权衡逻辑 |
| ❌ 怎么选进攻目标 | 只有 `MAX_RAID_DISTANCE` |
| ❌ 怎么分配兵力 | 完全没提 |
| ❌ 任务优先级怎么排 | 只有数量，没有排序 |
| ❌ "绝望"之后干什么 | 有阈值，**没行为** |

**为什么 P 社这么做**【推测】：

| 原因 | 说明 |
|---|---|
| 性能 | CK3 有几万角色，每个都跑脚本权重会卡死 |
| 可控性 | AI 是体验核心，不让 mod 改坏 |
| 防剧透 | 玩家读不到"AI 何时宣战"，保持挑战性 |

> 这印证了 `docs/后续制作方向.md` 里的判断：**「CK3 后期卡顿主因：AI 运算复杂 + 角色数量爆炸」** —— 正解释了它为何把 AI 挪进 C++。

**🔴 对我们的意义**：

| | CK3 | 我们 |
|---|---|---|
| AI 逻辑 | C++ 闭源，**改不了** | Lua 明文（`scripts/ai/AIManager.lua`），**随便改** |
| 能学到的 | 只有**节奏参数** | — |

**能借鉴的（架构层面）**：

| 借鉴点 | 怎么用 |
|---|---|
| **分层 tick** | 短/中/长任务用不同频率，别每帧全算 |
| **任务预算上限** | `MAX_TASKS_IN_TICK = 192` —— 防卡顿 |
| **负载均衡** | `MAX_TICK_STALENESS = 8` —— 忙不过来就摊到后续帧 |
| **预算分类** | 战备金/长期/短期分开管 |
| **"绝望"阈值** | 国破时切换行为模式 |

**🔴 想看 AI 决策逻辑，应该去 EU4 / HOI4** —— 它们的 AI 权重是**明文的**（`ai_will_do` / `common/ai_strategy/`）。**CK3 这块学不到。**

## 三、玩家操作流程

### 3.1 组建军队

```
1. 打开「军事」面板
2. 征召兵（Levy）：从领地自动获得，不能选兵种
3. 常备军（Men-at-Arms）：花钱买，**买的时候自选兵种**
   ⚠️ 比例在购买时定死，将军不决定比例
4. 补员：每月补 10%，各团按自己原比例独立补
```

### 3.2 打仗

```
1. 宣战（需要宣战理由 Casus Belli）
2. 把军队移到目标省份 → 自动开战
3. 战斗中：
   - 前 14 天不能撤退（早期阶段）
   - 之后可以手动撤退
   - 每 3 天将领掷骰争取「优势」
4. 一方坚韧耗尽 → 战败
5. 追击阶段：胜方追杀 3 天
6. 打赢 → 获得战争分数
```

### 3.3 战争分数怎么攒

| 来源 | 数值 |
|---|---|
| 单场战斗（攻方） | 最多 `80` |
| 战斗总分（攻方） | 最多 `100` |
| 占领省份 | 按省份价值 |

到 **100** 就能强制对方接受和约。

## 四、设计意图 —— 为什么玩家会开心

| 技巧 | 为什么这样设计 | 玩家感受 |
|---|---|---|
| **兵种有相克** | 不能一招吃遍天，要侦察对手 | 「我得看看他带什么兵」 |
| **重骑兵伤害是散兵 10 倍** | 精锐要有压倒性价值 | 「养一支重骑真值」 |
| **早期阶段不能撤** | 决策有代价，赌一把有紧张感 | 「要不要all in？」 |
| **追击阶段** | 打赢要能扩大战果 | 「别让他跑了！」 |
| **每 3 天将领掷骰** | 加随机性，弱者有机会 | 「我的神将又掷高了」 |
| **征召兵不能选兵种** | 常备军才有编制自由 | 「常备军才是我的精锐」 |

## 五、我们能借鉴什么

### 5.1 立即可用（对应现有文件）

| 借鉴点 | 改哪里 | 优先级 |
|---|---|---|
| **伤亡公式基准**（详见 §5.3） | `scripts/systems/CombatRules.lua` | 🔴 高 |
| **兵种数值关系修正** | `scripts/data/Units.lua` | 🟡 中 |
| **相克系数**（-90% 上限） | `scripts/data/Units.lua` 的 `vs` | 🟡 中 |

### 5.2 兵种数值对比 —— 我们的问题

`Units.lua` 注释写着「数值整套照抄 CK3 Men-at-Arms」，**但实际并不是**：

| 兵种 | CK3 伤害/坚韧 | 我们伤害/坚韧 | 问题 |
|---|---|---|---|
| 轻步兵 | 10 / **16**（坚韧 > 伤害） | 50 / 35（伤害 > 坚韧） | ❌ **关系反了** |
| 弓兵 | **25** / 10（脆皮高输出） | 75 / 85（反而耐打） | ❌ **关系反了** |
| 重骑兵 | **100** / 35（是散兵的 10 倍） | 115 / 90（只有 2.3 倍） | ❌ 兵种差距被抹平 |

**后果**：CK3 里「散兵耐打、弓兵脆皮、重骑碾压」的**战术差异消失了**，我们的兵种之间几乎只有数值大小之分，没有性格之分。

**建议**：要么真正照 CK3 的关系重写（散兵坚韧>伤害、弓兵伤害>>坚韧、重骑伤害极高），要么在文档里**删掉「照抄 CK3」这个说法**，承认是我们自己的数值。

### 5.3 🔴 伤亡公式（我们已确认的 bug）

**CK3 的做法**（⚠️ **【社区反推】,非文件确证**）：伤害 ∝ **敌方伤害 ÷ 自身坚韧**

> ⚠️ **诚实说明**：这个**方向**是社区一致认同的（且与"坚韧耗尽结束战斗"的逻辑自洽），
> 但**精确公式给不出** —— 原版文件里**只有常量，没有公式**（见 §二开头）。
> 两处 wiki 对"优势加成"分别说 +1%/点 和 +5%/点，而文件里是 `= 2`，**三个数都不一样**。
> **所以下面的修法依据的是"逻辑正确"，不是"照抄 CK3"。**

**我们的做法**（`CombatRules.lua:43-51`）：

```lua
result.attLoss = min(attBefore, max(MIN_LOSS,
    floor(dPower / total * attBefore * BATTLE_DAILY_LOSS_MAX)))
--                    ↑ 攻方伤亡 ∝ 攻方【自己】的人数
```

**实测复现**（用我们自己的参数模拟）：

| 攻方 | 守方 | 天数 | 攻方余 | 守方余 |
|---:|---:|---:|---:|---:|
| 1,200 | 50 | **15** | 1,176 | 11 |
| 5,000 | 50 | **15** | 4,976 | 11 |
| 10,000 | 50 | **15** | 9,976 | 11 |
| 50,000 | 50 | **15** | 49,976 | 11 |

**兵力翻 40 倍，天数完全一样** —— 这就是「1200 打 50 拖 12 天」的根因。

**修法**：把伤亡基准从「自己的人数」改成「敌方战力 ÷ 自身坚韧」。

### 5.4 结构性改造（大工程，另议）

| 借鉴点 | 说明 | 风险 |
|---|---|---|
| **四阶段** | 机动 → 早期(不可撤) → 后期(可撤) → 追击 | 中高，要动溃退逻辑 |
| **坚韧耗尽替代士气** | 战斗结束条件 | 中，要改 UI |
| **战斗宽度** | 限制同时参战人数 | 中，要改调军 |

> ⚠️ 这些是「要不要换成 CK3 那套设计」的**独立决策**，不该和 bug 修复混在一起。

### 5.5 🔴 「拿不到的部分」到底还有没有用

**这是本文最重要的一节。** 很多人会以为"拿不到精确公式 = 白研究了"，**恰恰相反**。

#### 把"拿不到的"按价值排序

| 拿不到的 | 对我们有用吗 | 为什么 |
|---|---|---|
| **伤害公式的精确系数** | ❌ **几乎没用** | 见下面的实验 |
| **AI 决策的具体权重** | ❌ **没用** | 几万行 C++，逻辑绑死 CK3 的人物/头衔体系 |
| **战斗宽度的精确算法** | 🟡 **有点用** | 但兵力规模差太远 |
| **软伤亡→硬伤亡的转化率** | 🟡 **思路有用，数值没用** | 概念可学，数值要重调 |

#### 实验：照搬 CK3 公式，我们的游戏会**变坏**

假设把 CK3 的 `0.03` 系数直接搬到我们的数值体系上：

```
我们的轻步兵：伤害 50（每团 100 人）

1,200 兵  → 总攻击  600  → 每日伤害  18
5,000 兵  → 总攻击 2500  → 每日伤害  75
10,000 兵 → 总攻击 5000  → 每日伤害 150
```

**结果：打 50 人的守军要 10 天，打 5000 人要 1000 天。**

**为什么？** 因为 `0.03` 是**配 CK3 的数值体系**设计的：

| | CK3 | 我们 |
|---|---|---|
| 轻步兵伤害 | **10** | **50**（放大 5 倍） |
| 战斗时长 | 8~12 天 | 我们自己定 |

**同一个 `0.03`，配上不同的兵种数值，结果差 5 倍。**
→ **`0.03` 脱离 CK3 的体系就是废纸。它不是"普适真理"，是"和另外几十个数值互相咬合的一个齿轮"。**

#### 能用的，是它背后的"设计意图"，不是数字本身

| 拿不到的 | 我们能提取什么 | 怎么用 |
|---|---|---|
| 伤害公式 | **"伤害 ∝ 攻击，不 ∝ 自己人数"** ← 这个**思路** | 修我们的 bug（**这个我们已经拿到了**） |
| 战斗宽度 | **"限制同时参战，防止人海无脑碾压"** | 想做时自己设计 |
| AI 决策权重 | **"AI 要分层思考、有预算上限"** | 架构思路（见 §2.7） |
| 精确系数 | ❌ **什么都提取不到** | 本来就不该要 |

**关键区分**：

```
设计意图  ← 能学，而且有价值  ✅
具体数字  ← 脱离原体系没意义   ❌
```

#### 反过来：我们"拿得到"的，才是真正值钱的

| 拿得到的（A 级，100% 精确） | 价值 |
|---|---|
| 41 个兵种的完整属性表 | ✅ 直接能对照 |
| 所有战斗常量（20+ 个） | ✅ 精确 |
| 相克关系（谁克谁、系数） | ✅ 精确 |
| 地形加成表 | ✅ 精确 |
| 四阶段划分、时长 | ✅ 精确 |
| **CK3 没有野战士气** | ✅ **推翻了我们文档里的错误记载** |
| **CK3 没有 `common/ai/`** | ✅ 解释了它的 AI 架构 |

**这些才是"照抄就有用"的部分 —— 因为它们是"内容"，不是"算法"。**

#### 打个比方

```
你想做一道好菜
├── 邻居的菜谱（精确公式）      → 拿不到
├── 但你知道"要放盐"（设计意图）  → 拿到了 ✅
├── 而且你的厨房和邻居不同（数值体系）→ 照搬反而难吃
└── 你的菜现在太咸（你的 bug）   → 和邻居无关，自己就能调
```

## 六、不能拿的（版权边界）

| 不能做 | 为什么 |
|---|---|
| 复制 `00_defines.txt` / `00_maa_types.txt` 进项目 | 那是 P 社的文件，受版权保护 |
| 照搬它的脚本代码 | `scripted_effects` / `on_action` 是 P 社写的 |
| 用它的美术/图标/文案 | 独立版权 |
| 把数值表原样搬进 `Units.lua` 发布 | 数值本身争议小，但**成体系的照搬**有风险 |

**可以做的**：

- 读它、理解机制、**用自己的代码重新实现**
- 借鉴**设计思路**（如「散兵耐打、弓兵脆皮」这种关系）
- 数值作为**参考**，但建议调成自己的体系

**记录要求**：如果最终采用了某些数值，建议在 `Units.lua` 头部注明来源与许可情况。
