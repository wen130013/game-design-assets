## 一、🔴 维3 的 UI 定义语法（可参考的范式）

> **来源等级：【文件确证】** —— `game/gui/battle.gui`（50 KB）

### 1.1 声明式 UI（和你的 `urhox-libs/UI` 思路一致）

```txt
types battle_panel_types
{
    type battle_panel = default_block_window_two_lines {
        name = "battle_panel"
        datacontext = "[BattlePanel.GetBattle]"      # ← 数据绑定

        blockoverride "window_header_name"
        {
            text = "[LabelingHelper.CapitalizeOnlyFirst(Battle.GetName)]"
        }

        blockoverride "goto_properties" {
            onclick = "[Battle.ZoomToMapMarkerPosition]"   # ← 点击行为
            tooltip = "ZOOM_TO_BATTLE"                      # ← 提示
            enabled = "[Not( Battle.IsZoomingToMapMarkerPosition )]"  # ← 禁用条件
        }
    }
}
```

### 1.2 🔴 三个值得注意的设计

**① `datacontext` —— 数据绑定**

```txt
datacontext = "[BattlePanel.GetBattle]"
```

**界面元素直接绑定到数据对象**，数据变界面自动更新。

**② `blockoverride` —— 模板覆写**

```
先定义"默认窗口"模板
再按需覆写其中的块（header / 按钮 / 显隐）
```

> 💡 **这和你 UI 库的"组件 + props"是一个思路**，但更彻底 ——
> 它连"继承模板再改一块"都做了。

**③ `enabled` / `visible` 是表达式**

```txt
enabled = "[Not( Battle.IsZoomingToMapMarkerPosition )]"
visible = "[Front.IsValid]"
```

**不是布尔值，是可求值的表达式** —— 界面能"自己判断"。

## 二、🔴 AoH3 的操作体验（为什么玩家觉得"直观"）

> **来源等级：【社区】** —— 这部分来自 wiki/社区资料，**不是文件确证**

### 2.1 地图交互三件套

| 操作 | 做法 |
|---|---|
| **缩放** | PC 滚轮 / 移动端双指 / 侧栏按钮 |
| **选中省份** | **点击即选** |
| **多选** | PC `Shift+点击` |

> 💡 **"点即选、拖即移、滚即缩"** —— 零学习成本，符合所有人对地图的直觉。

### 2.2 信息可达性

| 设计 | 说明 |
|---|---|
| **内建百科** | 游戏内解释大部分机制 |
| **军队数字可开关** | 设置里控制"显示军队数字" |
| **UI Scale** | 主菜单设置（0/1/2 三档） |

> 💡 **"内建百科"强烈值得借鉴** —— 降低"不知道能干嘛"的挫败。
> 你 `docs/后续制作方向.md` 也提到"完整新手引导"。

### 2.3 占领的可视化（条纹 → 实色）

| 状态 | 显示 |
|---|---|
| 已占领未同化 | **条纹色** |
| 同化完成 | **实色** |

> 💡 **可视化的"未完成感"** —— 玩家一眼看出"这块还没消化"。
> **你已经有"占领斜纹"**（`TODO.md` 记录），思路一致。

## 三、各游戏的操作流程对照

### 3.1 地图交互

| 游戏 | 缩放 | 选中 | 多选 |
|---|---|---|---|
| **AoH3** | 滚轮/双指/按钮 | 点击 | Shift+点击 |
| CK3 | 滚轮 | 点击 | — |
| EU4 | 滚轮 | 点击 | — |
| HOI4 | 滚轮 | 点击 | — |

### 3.2 面板组织

| 游戏 | 特点 |
|---|---|
| **维3** | 149 个独立 `.gui` 文件，**每个面板一个文件** |
| HOI4 | 国策树是**可视化的树**（有 x/y 坐标） |
| CK3 | 人物卡片式 |
| AoH3 | 极简，**内建百科** |

### 3.3 信息密度

| 游戏 | 风格 |
|---|---|
| 维3 | **极高**（一个面板几十个数字） |
| HOI4 | 高（国策树 + 生产） |
| CK3 | 中（人物卡片） |
| **AoH3** | **低**（对休闲玩家友好） |

> 💡 **你 `docs/后续制作方向.md` 提到"手机优先布局"** ——
> **AoH3 的低信息密度 + 内建百科，比维3 的高密度更适合手机。**
