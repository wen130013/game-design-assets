## 一、🔴 CK3 建筑（官方文档最完整）

> **来源等级：【官方文档】** —— `common/buildings/_buildings.info`

### 1.1 完整字段（官方原文节选）

```txt
name_of_the_building = {
    # 🔴 产出
    levy = 200                          # 给多少征召兵
    max_garrison = 100                  # 给多少驻军
    garrison_reinforcement_factor = 0.01

    # 🔴 建造
    construction_time = 720             # 建造时间
    cost = { gold = 500 }
    type = regular / special / duchy_capital

    # 🔴 三种修正器（作用域不同！）
    character_modifier = {}             # 给持有者
    province_modifier = {}              # 给省份
    county_modifier = {}                # 给郡

    # 特殊修正器
    duchy_capital_county_modifier = {}  # 给公国所有法理郡
    county_holding_modifier = {
        holding = castle_holding
        income_mult = 1
    }

    # 🔴 升级链
    next_building = castle_02           # 下一级建筑

    # 🔴 建造条件
    is_enabled = {}
    can_construct_potential = {}
    can_construct_showing_failures_only = {}
    can_construct = {}
    show_disabled = yes/no

    # 🔴 AI 权重
    ai_value = {
        base = 100
    }

    # 图形
    asset = { type = pdxmesh  name = "..." }
    is_graphical_background = no
}
```

### 1.2 🔴 三种修正器的作用域（重要）

| 修正器 | 作用 |
|---|---|
| `character_modifier` | 给**持有者**（如 +1 管理） |
| `province_modifier` | 给**省份**（如 +0.05 发展） |
| `county_modifier` | 给**郡**（更大范围） |

> 💡 **同一建筑可以对不同层级产生不同效果** ——
> 这比"建筑只给一个 buff"灵活得多。

### 1.3 🔴 升级链（`next_building`）

**真实例子**（【文件确证】）：

```txt
common_tradeport_01 = {
    construction_time = quick_construction_time
    cost_gold = normal_building_tier_1_cost
    province_modifier = { monthly_income = normal_building_tax_tier_1 }
    county_modifier = { development_growth_factor = 0.05 }
    next_building = common_tradeport_02        # ← 升到 02
    ai_value = { base = 10 }
}

common_tradeport_02 = { ... next_building = common_tradeport_03 }
...
common_tradeport_08 = { ... }                   # 到 08 封顶
```

**贸易港有 8 级**（01~08）。

> 💡 **升级是"链式"的** —— 一级一级升，不是一次建满。

### 1.4 AI 权重（明文）

```txt
ai_value = {
    base = 10
    ai_general_building_modifier = yes
    modifier = {
        factor = 4
        scope:holder.capital_province = this    # 首府 → 权重 ×4
    }
}
```

> 💡 **AI 建建筑是打分的** —— 首府优先。

### 1.5 建筑分类（按文件）

| 文件 | 大小 | 内容 |
|---|---:|---|
| `00_terrain_specific_buildings.txt` | **148 KB** | 地形专属 |
| `00_special_buildings.txt` | 75 KB | 特殊建筑 |
| `00_castle_buildings.txt` | 54 KB | 城堡系 |

> 💡 **`terrain_specific` 最大（148 KB）** ——
> **地形专属建筑是重头戏**（山地建要塞、平原建农田）。

## 二、🔴 维3 建筑组（Building Groups）

> **来源等级：【官方文档】** —— `building_groups/00_building_groups.txt` 字段注释

### 2.1 关键字段（官方原文）

```txt
# parent_group = parent_group_key    # 父组（可继承）
# always_possible = yes/no           # 无视资源限制
# economy_of_scale = yes/no          # ⚠️ 规模经济
# is_subsistence = yes/no            # 自给自足型
# default_building = key             # 默认建筑类型
# capped_by_resources = yes/no       # 受资源上限约束
# discoverable_resource = yes/no     # 可发现资源
# depletable_resource = yes/no       # 会耗尽的资源
# can_use_slaves = yes/no            # 能用奴隶
# land_usage = urban/rural           # ⚠️ 用地类型
# cash_reserves_max = number         # 现金储备上限
# inheritable_construction = yes/no  # 易主后是否保留
# urbanization = number              # 每级提供的城市化
# should_auto_expand = trigger       # 自动扩建条件
# min_hiring_rate / max_hiring_rate  # 招聘速率
# is_shown_in_outliner = yes/no
# subsidized = yes
```

### 2.2 真实例子

```txt
bg_manufacturing = {
    category = urban
    always_possible = yes
    economy_of_scale = yes          # ⚠️ 规模经济
    cash_reserves_max = 25000
    should_auto_expand = { default_auto_expand_rule = yes }
}
```

### 2.3 🔴 三个值得注意的

**① `economy_of_scale`（规模经济）**

建筑等级越高，**产出效率越高** —— 鼓励"建大"。

**② `land_usage = urban/rural`（用地类型）**

建筑**占用土地资源** —— urban 占城市化、rural 占耕地。

> 💡 **这给"建什么"加了空间约束** —— 不能无限建。

**③ `should_auto_expand`（自动扩建）**

```txt
should_auto_expand = { default_auto_expand_rule = yes }
```

> 💡 **可以让建筑"自动扩建"** —— 减少微操。

## 四、AoH3 建筑（最简单）

> **来源等级：【文件确证】** —— `GV_Buildings.json`

```json
{
    "BUILDINGS_LIMIT_DEFAULT": 5,      // 普通省最多 5 个建筑
    "BUILDINGS_LIMIT_CAPITAL": 8,      // 首都最多 8 个
    "BUILDINGS_SLOT_PER_ECONOMY": 5.0  // 每点经济 +5 槽位
}
```

> 💡 **极简设计**：
> - 普通省 5 个槽，首都 8 个
> - 经济越高，槽位越多（`5.0 × 经济`）

**比 CK3 的复杂建筑树、维3 的建筑组，简单得多 —— 但对休闲玩家友好。**

## 六、我们能借鉴什么

### 6.1 值得学的（按优先级）

| 借鉴点 | 来源 | 为什么好 |
|---|---|---|
| **🔴 槽位限制** | AoH3（5/8）、维3 用地 | 防止无限建 |
| **🔴 链式升级** | CK3 `next_building` | 一级一级升，有养成感 |
| **🔴 多作用域修正** | CK3（角色/省/郡） | 同一建筑对不同层级有效果 |
| **地形专属建筑** | CK3（148 KB） | 你已有 `TerrainReal.lua` |
| **自动扩建** | 维3 | 减少微操 |
| **AI 权重** | CK3 明文 | AI 会自己建 |

### 6.2 🔴 最契合我们的：槽位 + 地形专属

**AoH3 的槽位**（【文件确证】）：

```json
"BUILDINGS_LIMIT_DEFAULT": 5,      // 普通省 5 个
"BUILDINGS_LIMIT_CAPITAL": 8,      // 首都 8 个
"BUILDINGS_SLOT_PER_ECONOMY": 5.0  // 经济越高槽越多
```

**简单，但有效。**

**CK3 的地形专属建筑**（148 KB，最大的一类）：

```
山地 → 要塞
平原 → 农田
森林 → 伐木场
...
```

> 💡 **你 `TerrainReal.lua` 已有地形数据** ——
> **"地形决定能建什么"是天然的契合点。**

### 6.3 一个组合建议（【推测】）

```
槽位限制（AoH3）
  + 地形专属（CK3）
  + 链式升级（CK3）
  + 边际成本递增（AoH3 经济）
= 一个简单但有深度的建筑系统
```

### 6.4 ⚠️ 不能照搬的

| 为什么 |
|---|
| CK3 的建筑绑死"城堡/城市/神庙"三种持有类型 |
| 维3 的建筑组绑死工业体系 |
| 我们的建筑应该是**春秋战国的**（粮仓/武库/学宫/市集） |
