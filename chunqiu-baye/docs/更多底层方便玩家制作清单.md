# 春秋霸业 · 更多底层（方便玩家制作）清单

> 更新:2026-09-29
> 说明:记录**"让玩家能基于本游戏做模组/做新玩法"**所需的底层能力。
> ✅ = 已完成;🔧 = 进行中;⬜ = 待开发;❓ = 待决策。
>
> **本文档的定位**：与 `制作清单.md` 分工不同 ——
> 那份记录**游戏本身**要做什么；这份记录**底层能力**要补什么，
> 目标是让玩家能做出更多东西（不只是改数值，而是新玩法）。

---

## 零、架构约定（先明确分层）

```
系统层（不可改）        ← 我们写的：时间 / 空间 / 地图 / 经济 / 国家 / 战斗…
        ↓  提供扩展点
模组层（玩家做）        ← 玩家基于系统拼出来的内容与玩法
```

**大原则**：
- 系统层要**通用**，不能只为"春秋霸业"写死
- 系统层通过**扩展点**（注册口）暴露能力，玩家不改我们的代码
- **一切模组化**（含本体内容，本体也走同一套扩展点）

---

## 一、现有扩展点（✅ 已具备）

玩家目前能做的：

| 扩展点 | 作用 | 文件 |
|---|---|---|
| `Modifiers.rule()` | 挂数值规则（如"征兵 +10%"） | `systems/Modifiers.lua` |
| `Modifiers.unrule()` | 撤销规则 | 同上 |
| `Hooks.on()` / `Hooks.off()` | 挂事件钩子（某事件发生时做某事） | `systems/Hooks.lua` |
| `UISlots.add()` | 往界面空位挂按钮/面板 | `ui/UISlots.lua` |
| `Events.add()` | 增加事件 | `data/Events.lua` |
| `Cultures.add()` | 增加文化 | `data/Cultures.lua` |
| `Resources.register()` | 增加资源 | `data/Resources.lua` |
| `ModManager` | 扫描 / 启用停用 / 游玩集 | `mods/ModManager.lua` |
| `ModPack` | 模组打包格式（含 manifest） | `mods/ModPack.lua` |

**结论**：**"改数值 / 加事件 / 加国家 / 挂 UI" 已经能做。**

## 二、缺口分析（⬜ 待补）

玩家**目前做不到**的，以及原因：

### 2.1 缺"单位/实体"这一层

| 世界盒子需要 | 现状 | 差距 |
|---|---|---|
| 单位能自由移动 | ❌ **没有"单位"概念** | 只有"省份驻军数字" |
| 单位有独立身份 | ⚠️ 角色有身份但**无坐标** | 角色和军队是两套东西 |
| 单位有 AI 行为 | ❌ 没有 | 现有 AI 是"国家级"的 |
| 几千个实体实时更新 | ❌ 没有这套循环 | 现在是"按天结算" |

**核心问题**：

```
角色（CharacterSystem）：有身份（名字/年龄/五维/特质），但**没有位置**
军队（army）          ：有位置（from/to 省 ID），但**没有身份**（只是个数字 size）
世界盒子的"单位"      ：既有位置，又有身份
```

**换句话说**：**角色缺"位置"，军队缺"身份"**。合起来才接近"单位"。

### 2.2 缺"角色级"系统（鬼谷八荒方向）

| 鬼谷八荒需要 | 现状 |
|---|---|
| 人物在地图上走动 | ❌ 没有 |
| 立绘对话系统 | ⚠️ 有 UI 能力，无对话系统 |
| 角色对战（技能/数值） | ⚠️ 有战斗，但是"省份对撞"不是"角色对战" |
| 修仙系统（境界/功法/门派） | ❌ 没有 |

### 2.3 模组生态的工程问题

| 问题 | 现状 | 影响 |
|---|---|---|
| **模组冲突检测** | ⚠️ 只有 `missingDeps`（依赖检查），**无冲突检测** | 两个模组改同一个省 → 后加载覆盖前者，玩家莫名 |
| **资源按需下载** | ⚠️ 引擎有 DWP（边玩边下），**本项目未用** | 模组带大量图片/音乐 → 包体爆炸 |
| **模组资源隔离** | ❌ 都堆在 `assets/`，分不清归属 | 关掉模组无法释放空间 |
| **存档兼容** | ⚠️ 加字段即不兼容老存档 | 玩家开关模组可能坏档 |

## 三、待决策项 ❓

### 3.1 平台定位（决定后续所有工作）

| 选项 | 说明 | 工作量 |
|---|---|---|
| **A. 内容模组平台** | 玩家能在本游戏基础上加内容（新国家/事件/人物/地图） | 中 |
| **B. 通用游戏平台** | 玩家能做出**完全不同的游戏**（世界盒子/鬼谷八荒那种） | **极大** |
| **C. 先把现有模组做强** | 先让玩家能改数值/加事件，以后再扩展 | 小 |

**用户口径（2026-09-29）**：
> "我们的底层逻辑就是时间、空间、经济、地图、国家这些…
>   这些无法修改的底层逻辑叫**系统**，玩家基于系统做东西。"

→ 倾向 **B**，但要分阶段。

### 3.2 素材策略

**已决策**：✅ **模组可带图片/音乐，但必须按需下载**（不进主包，玩家不用就不下）。

**待定**：
- 模组资源放哪？（独立目录 / 打包格式）
- 关掉模组时怎么释放？
- 单文件大小上限？

## 四、建议的推进顺序（⬜ 未开工）

> ⚠️ 以下均为**讨论结论**，尚未动手。动手前需用户确认。

### 阶段 0：模组工程基础（最实际，先做）

- [ ] **模组冲突检测**：两个模组改同一条数据时给出警告
- [ ] **资源按需下载**：接上引擎 DWP，模组素材不进主包
- [ ] **模组资源隔离**：每个模组一个目录，关掉即释放
- [ ] **存档兼容策略**：缺字段时用默认值，不炸老存档

**为什么先做这个**：不先解决，模组一多就乱；而且**不影响现有玩法**。

### 阶段 1：加"单位/实体"层（决定能不能做世界盒子）

- [ ] 给角色加 `x, y` 坐标
- [ ] 加"每帧更新所有单位"的循环
- [ ] 单位在地图上画出来
- [ ] 点击移动 + 寻路

**难度评估**（用户问过）：

| 目标 | 难度 | 说明 |
|---|---|---|
| 给角色加坐标 + 画出来 | ⭐⭐ | 半天 |
| 让角色能移动（点击走） | ⭐⭐⭐ | 1~2 天 |
| 加寻路（绕障碍） | ⭐⭐⭐⭐ | 现成算法，接入地图要时间 |
| 几十个单位实时更新 | ⭐⭐⭐ | 引擎扛得住 |
| **几千个单位实时更新** | ⭐⭐⭐⭐⭐ | 要空间分区 + 批渲染优化 |
| 单位有 AI 行为 | ⭐⭐⭐⭐ | 逻辑量大 |

**参照**：现有地图**同屏渲染几百个省份**流畅 → 引擎扛得住"几十~几百个实体"。
**真正的坎是"几千个"**。

**影响评估**（用户问过）：

| 会不会影响现有 | 说明 |
|---|---|
| ✅ 不影响 | 省份/经济/外交/战争（它们不认识"单位"） |
| ⚠️ 会碰 | 存档格式（加新字段） |
| ⚠️ 会碰 | 性能（多了每帧循环） |

**关键**：**可以在旁边加，不动现有的** —— 就像 `armies` 是独立的一样。

### 阶段 2：角色级系统（鬼谷八荒方向）

- [ ] 立绘对话系统
- [ ] 角色对战（不是省份对撞）
- [ ] 修仙/成长系统

**工作量**：**极大**（商业游戏是团队做好几年）。

### 阶段 3：可选模块化

**想法**：把"单位层"做成**可选模块** ——
不想要世界盒子玩法的玩家，游戏完全不受影响；想要的，打开这个模块。

- [ ] 设计模块开关机制
- [ ] 确保关闭时零开销

