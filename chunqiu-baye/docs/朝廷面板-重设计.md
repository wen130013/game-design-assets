# 朝廷面板 · 重设计文档

> 2026-09-29 起草。**只设计，不动代码**（用户要求）。
> 起因：用户反馈"朝廷里好像塞了太多东西，而且只有文字，还有这个框太小了"。

---

## 一、现状诊断

### 实测截图看到的

```
┌─────────────────────────────────┐
│ 朝廷                          X │
├─────────────────────────────────┤
│ [君主][官员][后宫][将军][人才]  │  ← 5 个页签挤一行
├─────────────────────────────────┤
│ 丞相      空缺         [任命]   │  ← 10 行，长得一模一样
│ 大将军    空缺         [任命]   │
│ 御史大夫  空缺         [任命]   │
│ 吏部尚书  空缺         [任命]   │
│ 户部尚书  空缺         [任命]   │
│ 礼部尚书  空缺         [任命]   │
│ 兵部尚书  空缺         [任命]   │
│ 刑部尚书  空缺         [任命]   │
│ 工部尚书  空缺         [任命]   │
│ 太史令    空缺         [任命]   │
└─────────────────────────────────┘
```

### 三个问题（用户说的"都有问题"）

| 问题 | 具体表现 | 根因 |
|---|---|---|
| **框太小** | 面板固定宽 420，窄屏挤 | `width = 420` 硬编码，没做响应式 |
| **塞太多** | 官员页 10 行一次全列 | 没有分组/折叠，所有职位平铺 |
| **只有文字** | 纯文字行，无视觉层次 | 没有头像、没有图标、空缺和有人的行**长得一样** |

### 更根本的问题

**这个面板把"官职表"当成了"人物界面"。**

对比 CK3 的朝廷（Council）：

| CK3 | 我们现在 |
|---|---|
| 每个职位一张**人物卡**（头像 + 名字 + 属性） | 一行文字 |
| 空缺 = **虚线框 + 加号** | 写"空缺"两个字 |
| 一眼看出**谁在哪、强不强** | 全是"空缺"，看不出差别 |
| 点卡片 → 侧栏详情 | 点行 → 弹窗 |

**结论**：不是"美化"问题，是**信息架构**问题。

## 二、现有数据（设计依据）

### 五个页签各自有什么

| 页签 | 内容 | 数据来源 |
|---|---|---|
| **君主** | 国君五维 + 特质 + 年龄 | `faction.leaderId` |
| **官员** | 10 个职位（三公/六部/学官） | `CharacterSystem.POSTS` |
| **后宫** | 妃嫔列表（位号 + 名字 + 年龄） | `CharacterSystem.consortsOf` |
| **将军** | 各省统帅 + 统兵上限 + 兵力/上限 | `faction.provinceCommanders` |
| **人才** | 在野人物，可花钱招募 | `CharacterSystem` 在野池 |

### 职位清单（10 个，可分三组）

```
三公   ：丞相、大将军、御史大夫
六部   ：吏部、户部、礼部、兵部、刑部、工部（尚书）
学官   ：太史令
```

**这就是天然的"分组折叠"依据** —— 三公 3 个、六部 6 个、学官 1 个。

### 角色字段（面板能显示的）

| 字段 | 说明 |
|---|---|
| `name` | 姓名 |
| `age` | 年龄 |
| `gender` | 性别 |
| `post` | 现任职位 id |
| `rank` | 后宫位号 |
| `loyalty` | 忠诚 |
| 五维 | `military` / `management` / `diplomacy` / `intrigue` / `learning` |
| 特质 | `CharacterSystem.traitText(char)` |

### 每个职位的影响（可做"悬停说明"）

```
丞相    → 金钱收入 +3%/点（政务）
大将军  → 征兵 +4%/点（军事）
御史大夫→ 稳定 +0.5/点（谋略）
吏部尚书→ 稳定 +0.4/点（政务）
户部尚书→ 金钱 +5%/点（政务）
礼部尚书→ 外交改善 +1.0/点（外交）
兵部尚书→ 粮草 +4%/点（军事）
刑部尚书→ 稳定 +0.4/点（谋略）
工部尚书→ 人口增长 +5%/点（学识）
太史令  → 金钱 +2%/点（学识）
```

## 三、重设计方案

### 3.1 面板尺寸（解决"框太小"）

| 项 | 现在 | 改成 |
|---|---|---|
| 宽度 | 硬编码 420 | **响应式**：`min(屏宽 × 0.92, 560)` |
| 高度 | 内容撑开 | **定高**：`min(屏高 × 0.82, 内容高)`，超出滚动 |
| 内边距 | 16 | 14（窄屏再收） |
| 行高 | 34~40 | **48**（手机手指友好） |

**关键**：手机上侧栏/弹窗占屏宽 92%，电脑上不超过 560。

### 3.2 官员页：分组折叠（解决"塞太多"）

```
┌──────────────────────────────────────┐
│ 朝廷                              X  │
├──────────────────────────────────────┤
│ [君主][官员][后宫][将军][人才]       │
├──────────────────────────────────────┤
│ ▼ 三公                               │  ← 可点，折叠
│   ┌────────────────────────────────┐ │
│   │ 丞相        空缺      [+ 任命] │ │
│   │ 大将军      空缺      [+ 任命] │ │
│   │ 御史大夫    空缺      [+ 任命] │ │
│   └────────────────────────────────┘ │
│ ▶ 六部（6）                          │  ← 默认折叠
│ ▶ 学官（1）                          │  ← 默认折叠
└──────────────────────────────────────┘
```

**默认只展开"三公"**，六部/学官折叠。这样一屏能看全，不再"塞太多"。

### 3.3 每行视觉层次（解决"只有文字"）

**空缺行**（虚线框，一眼看出空着）：

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
   丞相                    ＋ 任命
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

**有人的行**（实心，突出"这个人"）：

```
┌───────────────────────────────────┐
│ ▓▓  李斯（政务 4）      [罢免]    │   ← ▓▓ = 色块头像
│ ▓▓  铁腕 · 金钱 +12%              │
└───────────────────────────────────┘
```

**三个视觉差异点**：
1. **虚线 vs 实线** —— 空/有人一眼区分
2. **色块头像** —— 用势力色 + 姓氏首字（**不需要美术素材**）
3. **属性加粗上色** —— 4 以上金色（已有逻辑，保留）

### 3.4 头像方案（暂缓，用户说"等一下再说"）

记录备选，等用户决定：

| 方案 | 成本 | 效果 |
|---|---|---|
| 色块 + 姓氏首字 | 0 | 简洁，像 CK3 的低配版 |
| AI 生成头像 | 每张花积分 | 好看，但要为每个角色生成 |
| 不要头像 | 0 | 纯靠排版做层次 |

**设计上先按"色块 + 姓氏"预留位置**（40×40 圆形），将来换真头像不用改布局。

### 3.5 其他页签的对齐

| 页签 | 现状 | 改成 |
|---|---|---|
| **君主** | 五维横排，还行 | 保持，加大字号 |
| **后宫** | 一行"位号 + 名字 + 年龄" | 同样加色块头像，位号用颜色区分 |
| **将军** | 已有"驻 X · 统兵上限 Y" | 保持，加"兵力/上限"进度条 |
| **人才** | 在野列表 | 加"招募花费"和"属性预览" |

## 五、实施优先级（等用户拍板）

| 优先级 | 改动 | 收益 | 风险 |
|---|---|---|---|
| **P0** | 面板响应式宽度 | 解决"框太小" | 低 |
| **P0** | 官员页分组折叠 | 解决"塞太多" | 低 |
| **P1** | 空缺/有人行的视觉区分（虚线 vs 实线） | 解决"只有文字" | 低 |
| **P2** | 色块头像 | 提升观感 | 中（要改布局） |
| **P3** | 其他页签统一风格 | 一致性 | 低 |

**建议**：先做 **P0 + P1**（改动小、见效快），看效果再决定 P2。
