## 一、这是什么游戏

- **名称**：春秋霸业（游戏内标题「逐鹿九州」）
- **类型**：历史大战略（Paradox 风格），单机
- **题材**：春秋战国，中国本部 + 周边
- **平台**：TapTap 小游戏（手机为主，横竖屏见下）
- **引擎**：UrhoX（Lua 5.4）
- **状态**：可玩原型，核心循环已通

**一句话**：选一个国家，经营、打仗、任免人物、和谈割地，逐步统一。

## 二、怎么运行

### 项目结构（工作目录 = 项目根）

```
项目根/
├── scripts/          # 游戏代码（入口 main.lua）
│   ├── main.lua              # 入口 + 所有回调接线（3108 行，偏大）
│   ├── ui/GameUI.lua         # 全部 UI 面板（2443 行，偏大）
│   ├── map/MapRenderer.lua   # 地图渲染/点击/缩放/军旗（3586 行，偏大）
│   ├── systems/              # 经济/军事/外交/AI/战争/科技
│   ├── data/                 # 省份数据、地形、兵种表、地图包
│   └── save/                 # 存档
├── assets/           # 图片、字体、音频、地形
├── docs/             # 设计文档（含本文档）
└── dist/             # 构建产物（**不要提交**）
```

### 构建与预览

- 用**官方构建工具**构建（不是自己写脚本），入口 `scripts/main.lua`
- 改完代码 → LSP 诊断确认 0 Error → 构建 → 预览
- **不要**手写 `dist/` 里的文件，**不要**启动本地 dev server

### 关键约定（踩过坑的）

| 约定 | 说明 |
|---|---|
| 长度单位 | **米**；Y-up 左手坐标系（同 Unity） |
| Lua 数组 | **索引从 1 开始** |
| UI | 用 `urhox-libs/UI`，原生 UI 已废弃 |
| UI 显隐 | 用 `Show()/Hide()`，**不要**改 `props.display` |
| NanoVG | 必须用 `NanoVGRender` 事件；字体只在 `Start()` 建一次 |
| 鼠标按钮 | 用枚举 `MOUSEB_LEFT`，不要用数字 |
| 对象释放 | 用 `Dispose()` |

- 经济：人口、钱粮、月度结算、欠费惩罚（逃兵/哗变）

- 和谈：割地、赔款、附庸、吞并；精准停战，不误停第三国战争
- 存档：完整军事状态（部队/路线/兵源/战斗/战争快照/和谈）往返
- 人物：君主、官员、后宫、生育、继承、游方士人
- 外交：宣战、改善关系、月度漂移

### 已知问题（**接手方优先看这段**）

以下问题已在 2026-10-08 排查确认，**尚未修复**：

1. **行军到达判定不一致**
   - 军旗按"游戏进度"移动（`MapRenderer.lua:2737`）
   - 实际到达还需"现实至少 3 秒"（`MilitarySystem.lua:613-615`、`GameConfig.MIN_MARCH_REAL_SEC=3`）
   - 20 倍速下一跳 0.15 秒就走完，却要等 3 秒 → **旗子到了、兵还没到**
   - 后果：多支部队与驻军画在同一点，**数字叠在一起**；暂停时该状态会一直留着

2. **占领省驻军旗画错国旗**（`MapRenderer.lua:2952`）
   - 用了 `live.ownerId`（正式归属），应改用实际控制方 `occupiedBy or ownerId`
   - 后果：燕军占领山戎的省，驻军仍显示**山戎旗**，看起来像敌军还赖在那

3. **兵力悬殊时战斗拖太久**（`CombatRules.lua:43-51`）
   - 伤亡按"受损方**自身**人数 × 12%"算，大军优势再大也压不快
   - 实测：1200 打 50，第 12 天才结束；10000 打 50 也是第 12 天
   - 需要改"悬殊战力下的伤亡/士气压力"

4. **途经有守军的省不接战**
   - 现状：多段行军只在**最终目标**省接战，中间站直接续令（`MilitarySystem.lua:624-638`）
   - 这是既有设计，但玩家会看成"走到敌省却不打"

5. **UI 状态显示不准**
   - 军队面板不区分"行军中/受阻/等待"（`GameUI.lua:1160-1177`），一律显示"还需 0 天"
   - 战斗详情面板战斗结束后可能仍显示旧数据（`GameUI.lua:1119-1159` 未校验战斗对象是否还在）

6. **战争终局未强制结算**（TODO #3）
   - 到 ±100 后输方停手，但不自动结算，需玩家点旗子

7. **军费基数待定**（TODO #5）
   - 现在每千兵每月 5 金 + 8 粟，兵力 ÷5 后几乎免费
   - 建议改成"每 100 兵"计费，**需先拍板口径**

8. **军队碎片化**（TODO #8，部分完成）
   - 战后残留小股驻军会累积（8 人、12 人到处是）
   - 渲染层已过滤小股，但数据仍在

9. **三个巨型文件**（开发效率瓶颈）
   - `MapRenderer.lua` 3586 行、`main.lua` 3108 行、`GameUI.lua` 2443 行
   - 远超业界建议的 800 行上限，**改大东西前建议先拆**

### 待拍板（需要用户决定）

## 四、接手方要做什么

### 第一步：跑起来

1. 确认引擎版本与构建工具可用
2. 用官方构建工具构建，入口 `scripts/main.lua`
3. 预览，确认能进主菜单 → 选国 → 进游戏

### 第二步：按优先级修已知问题

建议顺序（先修影响体感的）：

1. **行军到达判定 + 军旗叠放 + 占领军旗归属**（问题 1、2）—— 这三个是一组，直接决定地图观感
2. **悬殊兵力战斗节奏**（问题 3）—— 补数值用例再改
3. **UI 状态显示**（问题 5）—— 让玩家看懂"为什么不动"
4. **途经接战规则**（问题 4）—— 改前先想清楚是否影响既有移动语义

### 第三步：再谈新功能

新功能之前先问用户，不要自己开工。

### 铁律

- **改代码前先说明改动计划**，用户确认后再动手（用户常说"先别做"= 只要讨论）
- **小步验证**：一次只改一个点 → 验证 → 再改下一个
- **涉及多文件的大改先 commit 保底**
- **改动范围严格匹配用户要求**，不要顺手改别的系统
- **不凭记忆答**，涉及代码先读代码，涉及别的游戏先用工具查证
- **报告要诚实**：没做就说没做；构建通过 ≠ 用户验证通过
