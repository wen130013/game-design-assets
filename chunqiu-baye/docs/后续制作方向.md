# 春秋霸业 · 后续制作方向

> 记录"完善这款游戏还需要做什么"。
> 与 `制作清单.md`（已完成事项）、`更多底层方便玩家制作清单.md`（模组底层能力）分工不同，
> 本文档回答：**离"能发布的好游戏"还差什么。**
>
> 最后更新：2026-10-09

---

## 零、先说结论

现在是**有基础玩法循环的原型**，不是空壳。

**已有的**：经济结算、政策、征兵、混编兵种、行军、补给、战斗、占领、战争分数、
和约、科技、官员任免、人物生育与继承。

但 **"系统存在" ≠ "整局好玩、稳定、能发布"**。

⚠️ **不建议现在给"完成度百分之多少"** ——
国家战略游戏、人物王朝游戏、通用模组平台，三种目标的工作量完全不同。

---

## 一、离"完善"主要差在哪

| 方面 | 当前情况 | 需要补什么 |
|---|---|---|
| **电脑国家决策** | 会征兵、宣战、进攻、求和、改善关系 | 长期目标、财政安排、协同作战、战后恢复、科技与官员选择 |
| **战争完整流程** | 主要环节已有 | 验证"宣战→和约→下一场战争"全流程；明确围城与攻城兵是否要做 |
| **和平期玩法** | 有政策、科技、人物管理 | 确定玩家平时主要经营什么，避免"只等资源上涨、再打一仗" |
| **局势持续变化** | 有扩张、文化不满、复国基础 | 更连贯的事件、外交变化、发展阻力，让中后期仍有新局面 |
| **胜败与目标** | 有灭国失败、统一胜利 | 核对胜利是否可达；是否需要阶段目标、区域霸权、允许无限继续 |
| **存档可靠性** | 有存读档、版本迁移、模组校验 | 专项验证科技、在研项目、兵源、行军、战争等状态能否完整恢复 |
| **上手与难度** | 有说明和设置入口 | 完整新手引导；让难度、侵略度等设置真正影响玩法 |
| **手机与发布质量** | 已做不少适配 | 面板内容可达、长局性能、启动与内存、素材授权、异常处理 |

### 已发现的两个具体问题

1. **统一胜利检查遍历全部省份**，没有排除废土等区域
   → 需确认它与"可征服范围"是否一致
2. **存档逐项挑字段保存**，新增系统未必都存进去
   → 需要专项验证

> 这些不是"再加一个面板"能解决的。

## 二、AI 缺什么（不只是"调得更凶"）

这里的 AI 指**电脑国家的决策逻辑**，不一定需要联网，也不一定需要大模型。

**现状**：满足条件 + 按概率行动。例如比国力决定宣战、找相邻较弱驻军进攻、
科技按概率随机选。**不是乱来，但缺"前后连贯的打算"。**

- 主要入口：`scripts/ai/AIManager.lua:580`
- 科技选择：`scripts/systems/TechSystem.lua:166`

### 建议围绕六件事完善

| # | 方向 | 说明 |
|---|---|---|
| 1 | **先保证活得下去** | 预留军费和军粮；缺粮时少征兵，战败后先恢复，而不是继续扩军 |
| 2 | **有阶段目标** | 如守住边境、夺回失地、积攒兵源、发展经济。不要每月随便换目标 |
| 3 | **打仗前算收益与风险** | 不只看兵数，还看地形、补给、敌方援军、其他战争、攻下能否守住 |
| 4 | **多支军队围绕同一计划** | 哪些防守、哪些集结、哪些进攻、哪些撤退；避免各省各打各的 |
| 5 | **科技人才外交服务目标** | 缺军粮就优先相关发展；准备骑兵作战就研究对应科技；主动任命官员统帅 |
| 6 | **保留个性并能解释** | 守成、扩张、重外交的国家作不同选择；要能看出"为什么做"，才方便调整 |

### ⚠️ 一个必须先理清的工程问题

**现有代码里有两处自动进攻调度，其中一处也会替玩家出兵。**

→ 以后要先明确职责，**不能只改一套就以为军事 AI 已统一**。
→ 位置：`scripts/main.lua:2322`

## 三、GitHub 上值得利用的项目

> ✅ 许可已逐项核实，详见 `docs/开源许可核实.md`

| 项目 | 最值得利用的部分 | 复用注意 |
|---|---|---|
| **Unciv**（文明类） | 财政与扩军约束、建设收益评分、备战与宣战评估 | 可按许可条件移植，但**不是 Lua**，需适配 |
| **Freeciv**（文明类） | 内政与军事提出建议后统一比较；把长期科技需求传给前置科技 | 建议**优先研究方法**，直接复制须评估发行许可兼容性 |
| **TripleA**（地区棋盘战争） | 给多个进攻目标分配兵力、首都防御、判断攻下后能否守住 | 更适合作为**省份战争逻辑的参考** |
| **behaviourtree.lua**（Lua 决策库） | 执行"危机处理→防御→既定计划→普通发展"的优先流程 | **允许保留声明后复制修改**；提供骨架，不提供现成战略 |
| **LuaUnit**（Lua 测试工具） | 检查经济、兵力、科技前置、存档等规则 | 可复用；适合开发测试，**不能未经适配塞进正式游戏** |
| **Azgaar 地图生成器** | 随机地形、国家、城镇，还有省份行政区数据 | 允许使用生成地图；**优先用它的输出数据**，不必把整个生成器改写成 Lua |

### 复用策略（我的建议）

1. **能独立工作的通用组件，优先复制复用** —— 测试工具、决策执行骨架
2. **成熟游戏的决策模块，挑小块移植** —— 例如宣战评分、科技优先级，不搬整个游戏
3. **地图生成器，优先使用它的输出数据**
4. **我们的钱粮、兵种、官职、省份规则，只补连接部分** ——
   不重造完整基础工具，但也不能照搬别人不适合我们的数值

### 🔴 关于许可的重要纠正

**开源 ≠ 不能商用。GPL 也不是禁止商用。**

- Unciv 当前是 MPL-2.0，通常要求提供受其许可覆盖的文件及修改，
  **并不是自动要求所有独立游戏代码公开**
- 具体条件见 Mozilla 官方说明
- ⚠️ **但代码许可不能替代地图、字体、图片等第三方素材的授权** ——
  **免费上架也不能免去这一步**

## 四、成熟经验里最值得先学的四点

> 不是先追求一个很复杂的 AI。

1. **先列合法行动，再比较价值** —— 不能研究的科技、走不到的目标，先排除
2. **统一安排资源** —— 征兵、科研、外交不能各自把同一笔钱花光
3. **记录决策原因** —— 为什么宣战、为什么撤退、为什么缺粮，不能只记"执行了"
4. **自动跑长局并检查存档** —— 对比"连续玩下去"和"中途存读档后继续"，
   检查有没有丢状态；用固定随机条件重现问题

> 这类做法已有成熟项目可参考，不需要靠反复手点界面猜哪里出错。

## 五、确定的制作方向

| 项目 | 按你的意思推进 |
|---|---|
| **第一阶段** | 国家经营、战争、人物任免和继承，先做成**完整、稳定的一局** |
| **结束条件** | 设置里可选「任意一个 / 全部达到 / 关闭」，详见 §5.1 |
| **和平经营** | 先学习成熟游戏，再挑适合我们的做法，**不要求现在把所有规则想清楚** |
| **游戏设置** | 难度之外，还要有更丰富的人物、战争、经济等规则 |
| **开源复用** | 接受按许可要求公开被复用、修改的对应代码；具体项目逐个核对 |
| **玩家自建地图** | **暂不开放**；这一阶段不扩展地图创作功能 |

## 五之二、结束条件、失败处理与人物视角

> 本节记录用户 2026-10-08 明确的追求。**仍属讨论阶段，不开始制作。**

### 5.1 胜利条件设置（用户拍板）

设置里提供选项：

| 选项 | 含义 |
|---|---|
| **达到任意一个** | 满足任一胜利条件即结束（**推荐默认**） |
| **必须全部达到** | 所有条件都满足才结束 |
| **关闭结束条件** | 不因达成目标而结束，可一直玩下去 |

### 5.2 🔴 关闭结束条件后，国家被消灭怎么办

**这是和"关闭胜利条件"完全不同的另一件事**，必须单独决定。

用户方向：

- **可以像《十字军之王3》那样被囚禁**（不直接游戏结束）
- **转为旁观模式**，世界继续运行
- **可以选择成为另一个国家，或成为一个大臣**
- 🔴 **世界不要被删除**

### 5.3 主角死亡后的接续（用户拍板）

```
主角死亡
   ├─ 有后代  → 转为扮演后代
   └─ 无后代  → 转为旁观模式（世界继续）
```

旁观状态下，玩家仍然可以：

- 继续旁观世界演化
- 选择成为**任何一个国家**
- 或成为**大臣 / 官员 / 将军 / 诗人 / 游历者**

### 5.4 人物系统的目标：比 CK3 更强

> 用户原话要点："我们这个世界人物系统来说是比那个游戏要强很多，
> 因为我们可以充当各种官员呀、将军呀、诗人呀，还有各种…满世界乱窜的。"

**目标能力**：

| 能力 | 说明 |
|---|---|
| 扮演多种身份 | 君主 / 官员 / 将军 / 诗人 / 游历者… |
| 自由游历 | 人物可以"满世界乱窜"，不被国家边界限制 |
| 世界持续演化 | 玩家不当国家时，世界照常自己运行 |

**相关已有记录**（详细调查见 `制作清单.md`）：

- `制作清单.md` **H 节「个人视角模式」** —— 三层拆解（人物实体化 / 职位官署 / 玩家主体抽象）+ 4 条现状差距
- `制作清单.md` **I 节「看海 / 观察者模式」** —— 观战入口已完成，还缺 AI 意图可视化、外国情报面板

### 5.5 ⚠️ 必须正视的技术风险：CK3 为什么会卡

> 用户问："十字军之王3 为什么这么卡？"
> 查证结论（来源：Paradox 官方开发者日志 Dev Diary 187 + 社区性能模组说明）

**CK3 后期卡顿的主因**：

| 原因 | 说明 |
|---|---|
| **角色数量爆炸** | 500+ 角色或大家庭时，开销急剧增加 |
| **AI 运算复杂** | 后期 NPC 的阴谋、决策、关系网运算量巨大 |
| **单核优化不足** | 未充分利用多核 |
| **大型领地计算** | 税收、事件、决策随规模指数增长 |

**社区解决靠"削减人口"** —— 有专门的模组（A Culling of the Weak、
Population Control）**主动删掉低价值角色**来提速。

### 🔴 对我们的直接启示

**我们想做的人物系统"比 CK3 强很多"（各种身份、满世界游历），
恰恰是 CK3 卡顿的根源方向。**

因此从设计第一天就要定性能上限：

| 必须提前定的事 | 为什么 |
|---|---|
| **同屏/全图人物数量上限** | 不能无限生成人物 |
| **AI 决策频率**（不是每个角色每帧都算） | CK3 就是栽在这 |
| **关系网规模上限** | 关系是 N² 增长 |
| **"不重要的人"如何降级或淡出** | CK3 社区靠删人提速 |
| **游历人物的更新频率** | 几百个游历者同时算 = 灾难 |

**建议**：人物系统按"**分层模拟**"设计 ——
主角和重要人物精细模拟，边缘人物用简化规则或定期批量处理。
**这个决定要早做**，后期补代价很大。

### 5.6 ✅ 我们有更好的方法（不必重复 CK3 的坑）

> 用户观点（正确）："他卡顿不代表我们也会卡顿，肯定有更好的处理方法。"
>
> **更正一个误解**：CK3 是 2020 年的游戏，**不算老**。
> 它卡不是"年代久"，而是**设计选择** —— Paradox 选择**全量模拟地图上每一个角色**。

**我们的两个优势**：

1. **从零设计** —— 可以一开始就按性能友好的架构做，没有历史包袱
2. **模型更简单** —— 我们是**省份制**（2457 省），不是"每个角色都在地图上实时跑"

#### 具体可用的方法

| 方法 | 说明 | 效果 |
|---|---|---|
| **分层模拟（LOD）** | 主角/重要人物精细模拟；边缘人物用简化规则或**按月批量处理** | 最有效，CK3 社区靠"删人"变相达到类似效果 |
| **事件驱动** | 不用"每帧遍历所有对象"，改成"有事才计算" | 省掉大量空转 |
| **惰性求值** | 只在**需要显示或使用时**才算（如某省收入） | 避免算完没人看 |
| **时间分摊** | 把重活拆到多帧/多月做，不集中在一帧 | 避免卡顿尖峰 |
| **空间分区** | 查"附近"时只算邻近格子，不全图遍历 | 关系/邻接查询提速 |
| **关系网稀疏化** | 只记**有意义的**关系，设数量上限 | 关系是 N² 增长，必须限制 |
| **不需要的人"休眠"** | 变成统计数字，不再逐个模拟 | 数量可控 |
| **数据结构优化** | 大批量同类数据用"结构数组"而非"对象数组" | CPU 缓存友好 |

#### 结论

**性能不是"能不能做"的问题，是"设计时有没有考虑"的问题。**

- 只要**在设计第一天**就定好：数量上限、模拟频率、分层规则
- 就能做到"人物系统比 CK3 丰富"**同时不卡**

⚠️ 但**必须早做**。等人物系统铺开再补，改动量会大得多。

## 六、更多设置怎么做才真正有用

可以做得更丰富。建议**按类别组织**，而不是塞在一个长列表里：

| 类别 | 可考虑的规则（尚未制作） |
|---|---|
| **目标与结束** | 统一、霸权、期限结算、无结束条件 |
| **难度与电脑国家** | 资源加成、侵略倾向、扩张节奏 |
| **战争** | 迷雾、补给损耗、战斗节奏、自动调军 |
| **人物与继承** | 人物寿命、生育频率、人才出现频率、任免辅助 |
| **经济与局势** | 收入、军费、研究速度、叛乱与事件频率 |
| **操作与显示** | 字号、通知、自动暂停、地图显示 |

### 设计原则

- 参考《十字军之王3》社区规则资料的思路：**让玩家选择玩法**
- 可以比它提供更多针对本游戏的调整项
- 🔴 **每项都必须真的影响系统，不能只有按钮**
  （现状：设置面板里的难度下拉等仍是占位，写着"将随系统接入后生效"）
- 默认提供一套正常玩法，**高级设置**允许细调、保存预设
- 明确说明：**哪些规则只能开局选择、哪些可以中途改变**
