# 短剧编排工具 · 设计文档

> 2026-09-29 起草。目标：做一个**不用 AE** 的短剧/动态漫画编排工具，
> 用 Spine 骨骼动画驱动角色，导出视频。

---

## 一、要做什么（一句话）

**背景图 + 人物（骨骼动画） + 时间轴编排 → 导出 mp4。**

像这样：

```
舞台：一张背景照片
角色：从左走到右，中途挥手、转身、坐下
时间轴：什么时候做哪个动作、说什么话
输出：mp4（能发抖音/B站）
```

---

## 二、为什么不用 AE

| | AE | 本工具 |
|---|---|---|
| 上手难度 | 极难（关键帧、表达式、图层管理） | 简单（拖时间轴） |
| 费用 | 订阅制 | 免费 |
| 角色动画 | 要自己做绑定 | **Spine 现成** |
| 导出 | 手动渲染队列 | 一键 |

**核心判断**：你要的是"**纸片人动起来**"，不是特效合成。这是更简单的问题，AE 是杀鸡用牛刀。

## 三、技术可行性（已核实）

| 能力 | 状态 | 来源 |
|---|---|---|
| **Spine 骨骼动画** | ✅ 引擎内置 `UI.Spine` | `engine-docs/recipes/ui.md` § Spine |
| 多轨道 / 动画队列 | ✅ `SetAnimation(track, name)` | 同上 |
| 骨骼 IK 操作 | ✅ `FindBone` / `UpdateWorldTransform` | 同上 |
| 动画事件回调 | ✅ `SetCompleteListener` 等 | 同上 |
| 逐帧导出 | ⚠️ 无游戏内 API | 用命令行 `-screenshot` 逐帧跑（已验证可行） |
| 视频合成 | ✅ ffmpeg（沙箱内） | 已验证：libx264/x265/vp9/aac 全支持 |
| 角色序列帧 | ✅ sprite-gen skill | 图生序列帧 |
| 素材生成 | ✅ 图片/视频/音乐工具 | 沙箱内 |

**唯一需要绕的**：逐帧导出。方案见 § 五。

## 四、功能设计

### 4.1 三个核心概念

```
场景(Scene)  = 一张背景 + 若干角色 + 若干道具
角色(Actor)  = 一个 Spine 模型 + 位置/缩放/朝向
时间轴(Timeline) = 什么时候、谁、做什么
```

### 4.2 时间轴（核心界面）

```
时间(秒)  0    1    2    3    4    5    6
─────────────────────────────────────────
小明      [走→]      [挥手]      [转身]
小红            [进场]      [说话:你好呀]
BGM       ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓
字幕      ──────[好久不见]──────
```

**操作方式**（手机友好）：
- 点角色 → 底部弹出可用动作列表（走/跑/挥手/坐下/攻击…）
- 拖动作块到时间轴 → 定位
- 拖块边缘 → 调时长
- 点块 → 调参数（速度、方向）

### 4.3 动作库

每个角色自带一组动作（Spine 动画名）：

| 类别 | 动作 |
|---|---|
| 移动 | 走、跑、跳 |
| 交互 | 挥手、点头、摇头、鞠躬 |
| 战斗 | 攻击、防御、受伤、倒地 |
| 待机 | 站立、呼吸、说话 |

### 4.4 台词与字幕

- **字幕**：时间轴上拖一段，输入文字
- **配音**（可选）：我有 TTS 工具，能生成角色配音
- **口型**：Spine 有口型动画的话可以驱动（暂不做，优先级低）

### 4.5 镜头（可选，第二阶段）

| 效果 | 做法 |
|---|---|
| 推近 | 缩放场景 |
| 平移 | 移动场景 |
| 震屏 | 位置抖动 |
| 淡入淡出 | 透明度 |

## 五、导出方案（关键技术点）

### 问题

引擎**没有**游戏内逐帧截图 API。但有命令行 `-screenshot=<path> -screenshot-frame=N`（我一直在用）。

### 方案：确定性逐帧导出

```
① 工具里排好时间轴 → 存成 JSON
② 写一个"离线渲染"脚本：
     for frame = 0, totalFrames do
         设时间轴到第 frame 帧的状态（冻结，不依赖实时）
         截图 → frames/f0001.png
     end
③ ffmpeg 把 PNG 序列合成 mp4：
     ffmpeg -framerate 30 -i frames/f%04d.png -c:v libx264 -pix_fmt yuv420p out.mp4
```

**关键点**：必须**确定性**——同一帧号必须渲染出完全一样的结果。所以不能用实时播放（帧率不稳），要"直接设到第 N 帧的状态"。

### 成本

| 项 | 成本 |
|---|---|
| 帧序列渲染 | 0（本地 CPU） |
| ffmpeg 合成 | 0 |
| **总计** | **0 积分** |

**只有生成角色素材/背景/音乐才花积分，且一次生成可反复用。**

## 七、成本估算

| 项目 | 积分 |
|---|---|
| 角色 Spine 素材 | 每个角色一次（或找现成免费素材 = 0） |
| 背景图 | 每张一次 |
| 音乐/音效 | 每首一次 |
| **运行时（编排+导出）** | **0** |

**关键**：素材**生成一次，永久复用**。做 100 个视频，素材只花一次钱。

## 八、风险与限制

| 风险 | 说明 | 应对 |
|---|---|---|
| **Spine 素材从哪来** | 需要 `.skel`/`.json` + `.atlas` + PNG | 找免费素材站，或用 sprite-gen 生成序列帧替代 |
| **逐帧导出慢** | 一帧一次引擎启动 | 可优化：一次运行渲染多帧（待验证） |
| **确定性** | 实时播放帧率不稳 | 用"设到第 N 帧"而非"播放" |
| **手机性能** | 工具本身要能跑 | 编排在手机，导出可以在电脑 |
